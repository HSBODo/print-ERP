원데이(당일OP) 검사 건수 — 기존 전산(레거시)과 대시보드 비교

대상 기간: 2026-07-20 ~ 07-26 (07-26은 검사가 없어 실제로는 07-25까지) 비교 자료: 기존 전산에서 뽑은 검사자 리스트 엑셀 · 운영 DB 직접 조회 조사일: 2026-07-29

✅ 2026-07-30 반영 완료. §5의 수정(원데이 판정에서 "수술 중단이 아닐 것" 단서 제거)을 코드에 적용했다. 비교 주간 원데이는 93 → 98명이 되고, 월 단위로는 2026-01~07 각각 +18~42명 늘어난다 — §5 영향표 참고. 반영 결과(숫자·차트번호별 판정·구현 상태)만 보려면 → §6 반영 결과 요약 (구 "2탄" 문서를 이 문서로 병합)

한 줄 요약

같은 기간에 검사받은 사람은 양쪽 다 235명으로 똑같습니다. 빠진 사람은 없습니다. 다만 그중 몇 명을 원데이로 볼 것인가가 다릅니다 — 기존 전산 88명, 대시보드 98명.

숫자만 보면 10명 차이지만, 실제로는 18명이 서로 반대로 분류돼 있습니다. 대시보드만 원데이로 센 사람이 14명, 기존 전산만 원데이로 센 사람이 4명이라 서로 상쇄되면서 겉으로는 10명 차이로 보이는 겁니다.

결정된 것 (2026-07-29)

두 가지 애매한 경우를 어떻게 셀지 정했습니다.

어떤 경우어떻게 세기로 했나지금 대시보드는
당일OP로 오셨는데 수술을 못 하게 된 분원데이일반으로 세고 있었음 → 2026-07-30 고침 ✅
재수술을 당일에 받은 분일반이미 일반으로 세고 있음 → 그대로 둠

이 결정을 반영하면 대시보드 원데이가 93명 → 98명이 됩니다.

3. 왜 다른가 — 이유는 하나입니다

기존 전산과 대시보드가 서로 다른 예약을 봅니다.

무엇을 보고 검사 종류를 정하나
기존 전산그 환자의 가장 최근 예약 — 날짜와 상관없이, 아직 오지 않은 미래 예약까지
대시보드그 검사받은 날의 예약

원데이 검사를 받은 분은 그 자리에서 재검사 예약을 잡고 가십니다. 그러면 기존 전산은 나중에 잡힌 그 재검사 예약을 보고 "이 사람은 재검사 환자"라고 바꿔버립니다. 원데이에서 빠지는 거죠.

예를 들면

서동혁 님은 7월 21일에 원데이 검사를 받으셨습니다. 그런데 12월에 재검사 예약이 잡혀 있다는 이유로, 기존 전산에서는 7월 원데이에서 빠져 있습니다. 대시보드에서는 정상적으로 원데이로 잡힙니다.

이 방식의 문제

지나간 달의 숫자가 나중에 바뀝니다.

앞으로 예약이 하나 잡힐 때마다 기존 전산의 7월 숫자가 달라집니다. 지난주에 뽑은 7월 보고서와 이번 주에 뽑은 7월 보고서가 다를 수 있습니다.

대시보드는 그날 예약만 보기 때문에 한 번 지나간 달의 숫자는 바뀌지 않습니다. 마감된 숫자로 보고해야 하는 통계라면 이쪽이 안전합니다.

4. 다르게 잡히는 18명

결정을 반영한 뒤에도 아래 18명은 양쪽 분류가 갈립니다.

어떤 분들인원기존 전산대시보드
① 나중 날짜에 재검사 예약을 잡음11재검사원데이
② 같은 날 재검사를 한 번 더 함3재검사원데이
③ 재수술을 당일에 받음4원데이일반

대시보드만 원데이로 센 14명 − 기존 전산만 원데이로 센 4명 = 10명 차이

수술을 못 하게 된 5분은 결정 반영 후 양쪽 다 원데이가 되므로 여기서 빠집니다.

5. 반영 완료 (2026-07-30)

원데이를 세는 조건에서 "수술 중단이 아닐 것"이라는 단서를 뺐습니다.

원데이 = 그날 당일OP 예약이 있고 + 수술이 중단되지 않았을 것   (종전)
원데이 = 그날 당일OP 예약이 있을 것                            (현재)

재수술은 결정대로 계속 뺍니다 — 당일OP(M/5) 예약 자체가 없어서 자동으로 일반이 됩니다.

  • backend/src/main/resources/sql/softcrm/exam/select-all-exam-list.sql — 전체 검사자 리스트 원데이/일반 구분

기술 배경 (개발 참고)

레거시 분류 기준 재현 검증 레거시는 고객의 최신 M 예약(ORDER BY RESERVE_DATE DESC, RESERVE_NUM DESC, RESERVE_STATE <> 'C' — 미내원 'Y' 포함) 기준으로 검사유형을 정한다. 이 기준으로 재조회하니 6일치 검사OP 건수가 모두 정확히 일치(16/20/8/5/9/26)해 원인이 확정됐다. 우리는 backend/src/main/resources/sql/softcrm/exam/select-exam-list.sql#L92-L100에서 RESERVE_DATE = EXAM_DATE로 당일 예약만 본다.

원데이 판정 기준 — 변경 전 / 변경 후

  • 변경 전: 같은 날 RESERVE_FLAG='M' AND RESERVE_JINRYO='5'(검사OP) 예약이 RESERVE_STATE IN ('I','H')로 존재 + STOP_YN <> 'Y' + CANCEL_CD = ''
  • 변경 후: 같은 날 RESERVE_FLAG='M' AND RESERVE_JINRYO='5' 예약이 RESERVE_STATE IN ('I','H')로 존재 (중단/취소 조건 삭제)

RESERVE_JINRYO='7'(검사OP(Re) = 재수술 당일OP)은 결정대로 계속 제외한다.
