세 가지가 제기됐고, 셋이 서로 다른 문제였다. 785/784 차이와 VIVA 차이는 같은 원인이다.

총원 784는 맞다. 고칠 것은 ③·④ 두 가지다.

① ② 785의 정체 — 장은애 1명 (저쪽 오분류)

7월 시력교정 대상에서 시술명에 VIV가 들어간 건은 딱 둘뿐이다.

④ PIOL 합계 — 실인원 기준으로

piolSum(d) 는 하위 유형 단순 합이라 구조적으로 중복을 못 피한다. 두 갈래다.

  1. 집계에 piolPatients(DISTINCT 환자 수) 컬럼을 추가해 합계로 쓴다 — 정확하지만 마트까지 손댄다.
  2. 화면 라벨을 "유형 합(중복 포함)"으로 명시한다 — 코드는 그대로, 오해만 없앤다.

같은 성격의 중복이 라섹계·재수술 그룹 합계에도 있는지 함께 점검할 것.

⚠️ 화면 반영 조건

일별·월별 수술 유형 집계는 마트(mart_surgery_daily · mart_surgery_monthly)를 읽는다. SQL 은 배치 적재 소스라 재적재해야 화면에 반영된다.

① 프레스비욘드를 어느 칸에 넣을 것인가?

  • 별도 항목 신설(권장) — 노안 교정이라 라식·라섹과 성격이 다르다. 대신 마트~프론트까지 컬럼 추가가 따른다.

알려진 구조적 위험

백내장 제외가 기간 무관 전 이력 기준이다 (backend/src/main/resources/sql/softcrm/surgery/select-vision-monthly-by-type.sql#L54-L58).

7월에 시력교정 수술을 받은 사람에게 나중에 백내장 행이 생기면 7월 과거 수치가 뒤늦게 줄어든다. 7월 기준 해당자는 없지만, 과거 월 수치가 재조회 시점에 따라 달라질 수 있다는 뜻이다. "기간 내 백내장 수술" 기준으로 좁히는 안을 검토할 것.

조사에 쓴 쿼리

-- 7월 시력교정 대상의 원본 시술명 전수 (분류 CASE 적용 + 미분류 확인)
WITH eyes AS (
  SELECT o.CUST_NUM, o.OPERATIONR AS raw FROM OPERATIONDATA o WITH(NOLOCK)
   WHERE o.OPERATION_DATE BETWEEN '2026-07-01' AND '2026-07-31'
     AND RTRIM(ISNULL(o.OPERATIONR,'')) <> ''
     AND NOT EXISTS (SELECT 1 FROM Cataract_Operationdata co WITH(NOLOCK)
                      WHERE co.CUST_NUM = o.CUST_NUM)
  UNION ALL
  SELECT o.CUST_NUM, o.OPERATIONL FROM OPERATIONDATA o WITH(NOLOCK) /* 좌안 동일 */
)
SELECT RTRIM(raw) AS 시술명, COUNT(*) AS 안, COUNT(DISTINCT CUST_NUM) AS 환자
FROM eyes GROUP BY RTRIM(raw) ORDER BY 안 DESC;

-- VIVA 흔적 전수 (백내장 제외 없이)
SELECT * FROM OPERATIONDATA WITH(NOLOCK)
WHERE OPERATION_DATE BETWEEN '2026-07-01' AND '2026-07-31'
  AND (OPERATIONR LIKE '%VIV%' OR OPERATIONL LIKE '%VIV%');

-- 유형 중복(양안 다른 유형) 환자 수
SELECT COUNT(*) FROM (
  SELECT CUST_NUM FROM typed GROUP BY CUST_NUM HAVING COUNT(DISTINCT t) > 1
) m;
