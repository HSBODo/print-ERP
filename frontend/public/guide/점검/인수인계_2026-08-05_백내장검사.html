인수인계 — 백내장 검사 통계 개편 (2026-08-05)

✅ 재적용 완료 (2026-08-05) — §6 을 다시 실행하지 말 것

이 작업분은 개발자 브랜치 2026-07-29 @ fcaf2aa 위에 이미 재적용됐다(작업 위치: bnviit-dashboard-spring-3). 충돌은 frontend/src/pages/exam/routes.ts 의 import 블록 하나뿐이었고 양쪽 import 를 모두 살려 해소했다. §6-3 기준값 전부 통과 — 백내장 102/102·검사수 56·분류 45/11/40/6, 전체 리스트 1,204행, 원데이 561/643·빈칸 0, 중복 0건, 주간 종합지표 불일치 0, 아이리더 27종·22,180·가중합 110,625. 검사수 대조는 1~5월만 불일치(§5-6 골든시드라 정상).

아래 §1~§5 는 여전히 유효한 배경·함정 문서다. §6 은 이력으로만 남긴다.

1. 한 줄 요약

백내장 검사자 리스트가 레거시(BCRM) 102건 중 56건만 싣고 있었다. 모집단을 102로 넓히고 분류로 갈랐다. 월간 레포트 백내장 검사수는 56 그대로 두고, 늘어난 46건은 전체 검사수에만 더해진다. 곁들여 모집단 3중 불일치, 원데이 컬럼 빈칸, 중복 4건, 아이리더 장비명 분리를 고쳤다.

2. DB 배경 — 이거 모르면 아래 내용이 안 읽힌다

오늘 통합한 건 "테이블"이 아니라 "모집단 정의"다. 위 RESERVATION 갈래를 세 SQL이 각자 다르게 쓰고 있었다(§3 변경 3, 2026-07 기준 59 / 56 / 56). 테이블 구조는 그대로 두고 정의를 한 벌로 맞췄고, 테스트가 세 파일의 일치를 강제한다.

시력교정과의 통합도 마찬가지다. EXAM(시력교정) 과 RESERVATION(백내장) 은 별개 테이블이라 '전체 검사자'는 두 갈래를 UNION ALL 해서 만든다 — 합쳐진 테이블이 있는 게 아니다. 그래서 §3 변경 5의 중복이 생길 수 있었다.

2-3. 백내장 검사자 모집단 (세 SQL이 공유해야 하는 단 하나의 정의)

RESERVE_FLAG = 'H'
AND ISNULL(RESERVE_JINRYO,'') <> '3'    -- C_재검사 제외
AND ISNULL(RESERVE_SEQ, 0)   <> 3       -- 수술 당일 검사 제외
AND RESERVE_STATE NOT IN ('C','Y')      -- 실제 내원만
AND CUST_NUM <> '9999999999999'         -- 더미 고객
AND 테스트 고객 제외 (CUST_NAME LIKE '%테스트%' / '%test%')
집계 단위: 고객 × 검사일 (GROUP BY CUST_NUM, RESERVE_DATE)

담당자 배정 여부로 거르지 않는다. 그건 분류(§2-4)에만 쓴다.

변경 2 — 전체 검사수에 46건 합산 (백내장 검사수는 고정)

핵심 트릭. exam-session-source.sql 출력에 catClass 를 추가하고, isCat 의 뜻을 바꿨다.

isCat = 1  ⟺  분류가 '백내장' 또는 '중단'   ← 백내장 검사수 집계 대상(56)
catClass  = '' | '백내장' | '중단' | '노안/FU' | '기타'
  • COUNT(*) 쓰는 소비자(find-total-exam-count-monthly.sql, find-exam-count-by-class-monthly.sql) → 자동으로 +46
  • SUM(isCat) 쓰는 소비자(find-demographics-daily.sql) → 56 그대로. 이 파일은 수정 안 했다

⚠️ isCat 이름이 두 파일에서 뜻이 다르다. 이거 헷갈리면 숫자 틀어진다.

  • fragments/exam-session-source.sql → 백내장 검사수 집계 대상(56)
  • exam/find-all-exam-list.sql → 백내장 예약 행 전부(102)

레포트와 맞춰야 할 땐 isCat 말고 catClass IN ('백내장','중단') 을 쓸 것. 양쪽에 경고 주석 있음.

교체할 쿼리 — backend/src/main/resources/sql/exam/find-cataract-monthly.sql

SELECT yr, mo, COUNT(*) AS cnt
FROM (
  SELECT DISTINCT B.CUST_NUM
  FROM CUSTOM B
  JOIN RESERVATION D WITH(NOLOCK) ON D.CUST_NUM = B.CUST_NUM
  WHERE D.RESERVE_DATE BETWEEN :from AND :to
    AND D.RESERVE_FLAG = 'H'
    AND D.RESERVE_JINRYO <> '3'        -- C_재검사 제외
    AND D.RESERVE_SEQ  <> 3            -- 노안5진료실 제외
    AND D.RESERVE_STATE NOT IN ('C','Y')
    AND B.CUST_NUM <> '9999999999999'
) CH
JOIN CUSTOM B ON B.CUST_NUM = CH.CUST_NUM
WHERE EXISTS (SELECT 1 FROM EMPLOYEE E WHERE E.EMP_NUM = B.MY_OPTOMETRIST)   -- 검안사 배정됨
  AND ( B.MY_COUNSELOR = 'BS0808'                                            -- 중단
     OR EXISTS (SELECT 1 FROM EMPLOYEE E WHERE E.EMP_NUM = B.MY_COUNSELOR) ) -- 백내장
GROUP BY yr, mo

핵심은 검안사가 배정된 사람을 세는 것. 상담사가 BS0808(BS미지정)이면 중단, 배정돼 있으면 백내장 — 둘 다 포함한다.

⚠️ 레거시 원본의 (SELECT EMP_NAME ...) = (SELECT EMP_NAME ...) 패턴은 사실상 IS NOT NULL 검사다. MY_OPTOMETRIST IS NOT NULL로 옮기면 빈 문자열이 걸려 중단 65 / F/U 3으로 뒤집힌다. 반드시 EXISTS(EMPLOYEE)로 판정할 것.

-- AS-IS
UNION ALL
SELECT a.CUST_NUM AS cn, a.RESERVE_DATE AS d, 1 AS isCat, 0 AS isOneDay
FROM RESERVATION a WITH(NOLOCK)

  AND a.RESERVE_JINRYO = '1'

-- TO-BE : 백내장 검사자 리스트·월간 레포트와 동일 모집단. 고객당 1행(기간 내 첫 H 예약일).
UNION ALL
SELECT a.CUST_NUM AS cn, MIN(a.RESERVE_DATE) AS d, 1 AS isCat, 0 AS isOneDay
FROM RESERVATION a WITH(NOLOCK)
JOIN CUSTOM cb WITH(NOLOCK) ON cb.CUST_NUM = a.CUST_NUM
WHERE a.RESERVE_DATE >= :from AND a.RESERVE_DATE <= :to
  AND a.RESERVE_FLAG = 'H'
  AND ISNULL(a.RESERVE_JINRYO, '') <> '3'     -- C_재검사 제외
  AND ISNULL(a.RESERVE_SEQ, 0)     <> 3       -- 노안5진료실 제외
  AND a.RESERVE_STATE NOT IN ('C','Y')
  AND cb.CUST_NUM <> '9999999999999'
  AND NOT (ISNULL(cb.CUST_NAME,'') LIKE N'%테스트%' OR LOWER(ISNULL(cb.CUST_NAME,'')) LIKE '%test%')
  AND EXISTS (SELECT 1 FROM EMPLOYEE E WITH(NOLOCK) WHERE E.EMP_NUM = cb.MY_OPTOMETRIST)
  AND ( cb.MY_COUNSELOR = 'BS0808'
     OR EXISTS (SELECT 1 FROM EMPLOYEE E WITH(NOLOCK) WHERE E.EMP_NUM = cb.MY_COUNSELOR) )
GROUP BY a.CUST_NUM

  • 마트 재적재 필요 — ExamMartJob이 list_cataract_exam·all_exam_list를 delete+insert 하므로 대상 기간 재실행

  • 시력교정·드림렌즈 분기는 건드리지 않는다

남는 판단 (업무 확인)

통합 리스트 안에서 백내장만 검안사 배정 조건이 걸린다. 시력교정에는 없는 잣대다. 다만 이는 레거시 정의(검안사 배정 = 실제 백내장 검사 진행)를 따른 것이고 월간 레포트도 같은 기준이라, 화면마다 숫자가 다른 현재 상태보다는 낫다고 판단해 A안(백내장 리스트에 맞춤)을 택했다.

대안 B — 진료구분 제한만 풀고 검안사 조건은 걸지 않는 안. 통합 리스트 성격은 유지되나 백내장이 97명이 되어 레포트(54)와 어긋난다. 채택하지 않음.

남는 한계

분류가 CUSTOM의 현재 담당자 값을 참조하므로, 담당자가 재배정되면 과거 달 숫자도 소급 변동한다. 6월이 정확히 맞은 건 최근 달이라 아직 안 바뀌어서다. → 월 마감 스냅샷 저장 필요 (지표정의.md §3)
