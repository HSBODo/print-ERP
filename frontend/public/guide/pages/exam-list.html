2

사용자와 쓰임새

누가 여는가

레거시 CRM 의 「검사자 리스트(상담사별)」 화면을 그대로 옮겨 온 것임. 상담사·상담의·검안사가 붙은 검사 원장이라, 숫자를 보는 화면이 아니라 사람을 찾는 화면임.

쓰는 장면하는 일
상담 후속검사만 받고 수술로 안 간 사람을 추려 연락함 — 그래서 연락처가 화면에 있음
검사 중단 확인중단(Y)·취소사유·취소메모로 왜 멈췄는지 봄
수치 대조월별 검사자 종합지표·검사수와 명단 건수를 맞춤
견적·수납 확인견적가·수술가율·수납금액이 한 행에 있어 상담 결과를 되짚음
⚠️ ADMIN 전용 — 이 화면은 개인정보 덩어리임

주민번호 · 휴대전화 · 집전화 · 이메일 · 주소가 한 표에 다 있음. 대시보드에서 이만큼의 식별정보를 한 번에 펴는 화면은 이것과 백내장 검사자 리스트뿐임. 그래서 사이드바에서도 ADMIN 에게만 보이고, ADMIN 이 아니면 직접 URL 로 들어와도 placeholder 가 뜸.

이름이 오해를 부름

여기서 「검사자」는 검사를 받은 고객이지 검사를 배정받은 직원이 아님. 레거시의 uASSIGN1 검사배정현황과 다른 화면임.

기준 날짜는 검사일임

EXAM.EXAM_DATE

예약자 리스트가 등록일 기준인 것과 다름. 8월에 예약을 잡고 9월에 검사를 받으면 예약자 리스트는 8월, 이 화면은 9월에 나옴. 두 화면의 건수를 직접 비교하면 안 되는 이유임.

5

표 · 지표 정의

컬럼 정의의 정본은 따로 있음

51컬럼의 화면 라벨 ↔ API 필드 ↔ 원본 엑셀 열 번호 대응표, 실행 SQL 전문, 검사정보1~30 취급은 db/검사자리스트-컬럼정의.md 가 정본임. 여기서는 그 문서가 답하지 않는 것 — 모집단을 어떻게 자르고 파생값을 어떻게 만드는지 — 만 적음.

모집단 — 무엇이 한 행이 되는가

행 1개 = 기간 내 EXAM 의 검사 1건. 주 원천은 EXAM + CUSTOM 이고 수술·직원 정보는 OPERATIONDATA · EMPLOYEE 를 붙임.

규칙내용왜
기간EXAM.EXAM_DATE 가 조회 범위 안—
상담사 제한없음 — 전체 조회레거시는 상담사별로 갈라 보지만 여기선 한 표에 다 폄
테스트 제외고객명에 테스트·test·TEST검사메모·예약번호의 test 는 제외 기준으로 쓰지 않음 — "장용테스트"·"모노비전TEST" 같은 정상 임상 메모가 오탐됨
백내장 그림자 행 제외같은 고객·검사일에 Cataract_Exam 본행이 있고, EXAM 의 측정값(RIGHT01~30·LEFT01~30)이 전부 공백이면 뺌백내장 검사가 EXAM 에 껍데기 행을 남김. 그대로 두면 시력교정 검사자가 부풀어 오름
진료구분·예약 부가정보는 '같은 날 예약'에서 가져옴

검사일과 같은 날짜의 검사예약(RESERVE_FLAG='M', RESERVE_STATE IN ('I','H'))을 붙임. 예약 없이 내원해 검사만 받은 건은 이 칸들이 빔 — 데이터 오류가 아님.
