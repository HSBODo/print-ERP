2

사용자와 쓰임새

예약이 얼마나 들어왔는가, 한 장으로

검사예약 건수를 콜과 온라인으로 합산해 월별 추이로 봄. 예약 지표 중 가장 위에 있는 숫자이고, 아래로 예약통계_시력교정· 예약통계_백내장이 채널·주차로 분해함.

쓰는 장면하는 일
전년 대비 확인3개년이 겹쳐 있어 같은 달을 바로 비교함
채널 비중 확인탭을 바꿔 종합 · 온라인 · 콜을 오감
명단 확인숫자가 이상하면 예약자 리스트로 내려감 — 합계가 같음
예약자 리스트와 짝임

이 화면의 월 값과 예약자 리스트의 그 달 행 수가 같아야 함. 둘 다 카카오를 빼고 셈.

조회 조건과 필터

조회 조건은 연도뿐

조건어디서규칙
연도서버기본 3개년. GET /api/stats/reservation-overall/monthly?years=…

기간 선택기가 없음 — 항상 1~12월 전체를 그림.

기준 날짜는 등록일

예약자 리스트와 같이 예약을 잡은 날(InsertedDateTime) 기준임. 검사일이 아님.

표 · 지표 정의

탭 3종

탭포함 채널RESERVE_PATH
예약 종합콜 + 온라인CTI · CRM · ONLINE · APP · NAVER
온라인 예약홈페이지/앱 + 네이버ONLINE · APP · NAVER
콜 예약인콜 + 아웃콜CTI · CRM

종합 = 온라인 + 콜 임. 세 탭의 값이 이 관계를 만족해야 함.

⚠️ 카카오는 거의 안 잡힘

카카오톡 예약은 해피톡 채널이라 RESERVATION 에 거의 남지 않음. 탭 설명에는 "카카오톡"이 적혀 있지만 실제 값은 사실상 0 임. 예약자 리스트도 같은 이유로 카카오를 명단에서 뺌 — 그래서 두 화면 합계가 맞음.

연도별로 숫자의 성격이 다름

연도출처신뢰도
2024 · 2025레거시 BCRM 문의통계 확정값확정 — 변하지 않음
2026 ~운영 DB 추정치(검사예약 전체)당월까지만 신뢰할 수 있음
'추정치'인 이유

레거시 문의통계는 사람이 채널을 판단해 집계한 숫자였고, 2026 부터는 RESERVE_PATH 코드로 자동 분류함. 분류 기준이 완전히 같지 않아 연도 경계에서 단차가 생길 수 있음. 2025 → 2026 의 변화를 읽을 때는 이 점을 감안해야 함.

색 규칙

최신 연도부터 빨강(#E11D2E) → 회색(#4B5563) → 하늘색(#A8CEDF) → 주황(#F59E0B) 순으로 붙음. 연도를 몇 개 고르든 가장 최근이 항상 빨강이라, 해가 바뀌어도 읽는 법이 그대로임.

컬럼 정의 — 6개

연도별 선 차트와 월별 표가 같은 응답을 그리고, 탭은 다른 필드를 보여줌. 2026-06 이후는 시력교정 · 백내장 · 홈페이지 마트를 조회 시점에 합산함.

#화면 라벨응답 필드마트 컬럼CRM 원천비고
1연도(행 라벨 · 범례)yearyr—필터에서 고른 연도(기본 최근 3개년). 최신 연도부터 빨강→회색→하늘→주황. 최신 연도만 선이 굵고 값 라벨이 붙음
21월 ~ 12월month + 탭 필드(3~5번)mo—월 하나가 열 하나. 값이 null 이면 빈 칸이고 선도 끊김(connectNulls=false). 미래 달은 항상 null
3합계— (프론트 합)——그 행의 숫자 월만 더함. 0 이면 빈 칸. 마트의 total 을 쓰지 않음
4탭 「예약 종합」 값reservations (= total)reservations · total2024·2025: V12 시드 확정값(레거시 문의통계) / 2026-01~05: V24 골든값(담당자 확정) / 2026-06~: 온라인(5번) + 콜(6번)온라인이 null 이면 종합도 null. 연도 경계에서 산정 방식이 바뀜
5탭 「온라인 예약」 값onlineonline라이브 = 시력교정 마트 naver_reservation + kakao_reservation(월합, override 반영) + mart_list_reservation_homepage COUNT(*). 원천: RESERVATION(PATH NAVER · 비취소) · HappyTalk_Counsel_List(수술전 · ★신환) · 홈페이지 상담신청(CATEGORY='COUNSELONLINE')홈페이지 스냅샷 마지막 등록일 이후 달은 null. 네이버·카톡은 시력교정만, 홈페이지는 전 진료 포함(의도된 비대칭). 탭 설명의 '카카오'는 RESERVATION 이 아니라 해피톡에서 옴
6탭 「콜 예약」 값callcall_count라이브 = 시력교정 마트 call_reservation + tm_reservation + tm_recounsel_reservation + 백내장 마트 new_patient + tm_reservation. 원천: CtiRptLst · DB_CUSTOM · DB_ReCounsel(각 예약통계 표의 정의와 동일)탭 설명은 'RESERVE_PATH CTI·CRM' 이라 적혀 있으나 2026-06 이후 실제 계산은 예약통계 마트 합산임. select-monthly.sql(RESERVE_PATH 기준 MSSQL 직결)은 배치가 더 이상 쓰지 않음

배치(ReservationMartJob)는 같은 서비스로 계산한 값을 mart_reservation_overall_monthly 에 upsert 하되 2024·2025 와 2026-01~05 는 쓰지 않음(시드가 유일 원천). 셀 손보정(reservation_stats_override)은 예약통계 화면에서 하며, 2026-06 이후 달의 이 화면 값에 즉시 반영됨.
