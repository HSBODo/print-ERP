사용자와 쓰임새

두 개의 명단을 하나로 붙이는 화면

ECP 해외마케팅이 받은 접수 명단과 CRM 의 기존 외국인 고객은 원래 서로 모름. 접수는 구글 시트로 들어오고 진료는 CRM 에 남음. 이 화면은 둘을 사람 단위로 이어 붙여, 문의한 사람이 실제로 검사·수술까지 갔는지 한 줄에서 보이게 함.

쓰는 장면하는 일
매칭 확인자동 매칭이 애매하다고 표시한 건을 사람이 확정함
진행 추적문의 → 검사 → 수술 상태와 비용을 봄
수기 추가시트에 없는 접수를 화면에서 직접 넣음
통계 원천이 명단이 통계·예약통계의 밑값이 됨
다른 리스트와 성격이 다름

대시보드의 리스트는 대부분 읽기 전용인데, 이 화면은 원천 데이터를 직접 만드는 화면임. 행 추가·수정·삭제·매칭이 전부 여기서 일어남. 그만큼 규칙이 많음.

표 · 지표 정의

매칭 3단계

상태조건뜻
매칭customer_no 가 있음CRM 고객과 확정 연결됨
확인필요candidate_customer_no 만 있음
또는 미매칭인데 exam_date 에 실제 날짜가 있음		후보는 있으나 확신이 없음 / 내원 이력이 있으니 어딘가에 붙어야 함
접수둘 다 없음아직 CRM 에 붙지 않았음
검사일이 있으면 자동으로 확인필요로 올림

후보조차 없는데 검사 기록이 있다는 것은 CRM 어딘가에 이 사람이 있다는 뜻임. 접수로 두면 아무도 안 봄. 그래서 조회 시점에 승격시켜 사람이 처리할 목록에 넣음.

자동 매칭 규칙

결과조건
자동 매칭
matched_by='CRM_Sync'		 이름 + 생일이 유일하게 일치 (월일 스왑 허용)
전화 뒷8자리 또는 이메일로 유일 후보 + 생일이 일치하거나 스왑
확인필요유일 후보인데 생일이 다르거나 없음 — 근거를 candidate_reason 에 남김
월일 스왑을 허용하는 이유

해외 접수는 날짜 표기가 MM/DD 와 DD/MM 로 섞여 들어옴. 스왑을 허용하지 않으면 같은 사람이 계속 미매칭으로 남음.

수동 매칭이 자동보다 강함

고객번호 칸을 눌러 팝업에서 확정하면 matched_by 에 로그인 ID 가 저장됨. 이 매칭은 행 수정·시트 재동기화에도 보존됨. 반면 자동 매칭 행은 수정하면 매칭·스냅샷을 비워 다음 CRM 동기화에서 다시 계산함 — 사람이 고친 정보로 매칭이 달라질 수 있기 때문임.

조회는 마트만 읽음

값어디에 사나
접수 원본overseas_marketing_sheet — 시트 이관분 + 수기 입력
CRM 매칭customer_no · matched_at
파생값(상태·수술정보·비용·외래)crm_snapshot (JSON)
⚠️ 화면은 CRM 을 실시간으로 보지 않음

CRM 값은 스냅샷임. 갱신은 [CRM 동기화] 버튼으로만 일어남. CRM 에서 수술일이 바뀌어도 동기화를 누르기 전까지 화면은 옛날 값임.

동기화가 지켜야 하는 것

규칙내용
잠금시트 동기화가 지나간 행은 삭제 불가(locked_at), 수정만 됨
보존시트 동기화는 수기 행 · 화면에서 수정된 시트 행 · 수동 매칭 행을 덮지 않음
수기 행 표시origin='manual' + 추가자(created_by = 로그인 ID)
수정 범위시트 행은 시트 원본 컬럼에 한정해서만 고칠 수 있음
