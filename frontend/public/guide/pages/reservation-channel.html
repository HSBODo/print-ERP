사용자와 쓰임새

채널이 얼마나 데려오고, 어디서 놓치는가

예약자 리스트를 유입 채널로 묶어 예약 → 수술까지 단계별로 좁혀 봄. 합계는 예약자 리스트와 같고, 보는 각도만 다름.

쓰는 장면하는 일
채널 효율 비교어느 채널이 수술까지 데려오는지 봄 — 예약만 많은 채널을 걸러냄
이탈 지점 찾기단계 사이 낙차가 큰 곳이 그 채널의 약점임
수술 대기 파악수술등록 − 수술완료 = 아직 안 한 사람
짝이 되는 화면

퍼널이 얼마나 오나(전환 축)라면, 채널별 수익성은 얼마 버나(가치 축)임. 두 화면은 같은 뷰(v_reservation_channel)를 읽어 인원이 일치함. 채널의 성격 해석은 채널별 분석에 있음.

2026-08-06 에 예약 → 마케팅으로 옮겼음

예약 그룹에 있었지만 실제로 보는 것은 유입 채널의 효율이라 마케팅 섹션이 더 맞음.

구성 요소

영역구성동작
기간시작월 ~ 끝월월 단위 범위 조회임. 한 달만 볼 수도, 여러 달을 합칠 수도 있음
퍼널 밴드8단계단계 사이 낙차를 이탈로 그림
채널 표9칸 (8단계 + 수술대기)정렬 가능. 합계행은 채널 값을 더하지 않음 — 5장 참조
최종 전환수술등록 ÷ 예약재수술까지 세면 0 이라 수술등록이 기준임
수술대기를 퍼널 밴드에 넣지 않은 이유

대기는 등록의 부분집합이라 완료와 형제임. 밴드에 끼우면 735 → 156 → 579 로 줄었다 늘어 퍼널이 거짓말을 함. 완료 뒤에 두면 735 → 579 → 156 으로 계속 줄어 자연스러움.
등록과 완료 사이에 두는 것도 틀림 — "대기를 거쳐 완료로 간다"로 읽히는데, 대기와 완료는 서로 배타이고 완료한 사람도 전부 대기를 거쳤음. 대기는 오늘 기준 아직 안 한 사람의 스냅샷임. 그래서 이탈의 빨강이 아니라 노랑·점선으로 그림.

조회 조건과 필터

조회는 월 범위 하나

조건어디서규칙
시작월 ~ 끝월서버예약 등록일 기준. GET /api/stats/reservation-channel
수술 유형서버 (별도 API)/op-types — 채널별 수술 유형 분해

채널 필터가 없음 — 모든 채널이 항상 행으로 나옴. 유입이 0 인 채널도 포함함.

0 인 채널을 왜 남기나

빼면 "채널이 없는 것"과 "이번 달 0명"이 구분되지 않음. 게다가 달을 바꿀 때마다 행 수가 흔들려 표를 읽기 어려움. 채널 목록은 뷰 전 기간의 값에서 뽑으므로 화면에 이름을 하드코딩하지 않음 — 분류 규칙을 뷰에서 고치면 목록도 따라옴.

⚠️ 이 화면은 사람 수만 셈

같은 사람이 취소 후 다시 잡아도 1명임. "실제 몇 명이 왔나"가 알고 싶은 값이라서임. API 는 건수도 함께 주지만 화면은 쓰지 않음 — 숫자가 두 벌이면 읽기 어려움. (2026-07: 예약 1,555건 / 1,540명, 접수 935건 / 933명)

⚠️ 합계행은 채널 값을 더한 것이 아님

사람 수는 채널별 DISTINCT 라 한 사람이 두 채널로 예약하면 채널마다 1명씩 세어짐. 그래서 채널 합계 ≠ 전체 사람 수 임. 전체 기준 값을 서버가 따로 실어 보내고, 화면 합계행은 그 값을 그대로 씀. 표를 CSV 로 받아 세로합을 내면 합계행과 다르게 나옴 — 정상임.

사람 식별 — 4순위로 판정함

순위키인정 조건
①휴대폰숫자 9자리 이상이면서 0 만으로 이뤄지지 않을 것
②이메일@ 가 있을 것
③차트번호더미(9999999999999)가 아닐 것
④이름—
더미 번호를 거르는 이유

연락처를 모르는 예약에 0 을 채워 넣는 관행이 있음. 2026-07 에 00000000000 74건 · 0000 9건 · 0 4건이 있었음. 거르지 않으면 서로 다른 87명이 3명으로 뭉개짐. 식별 커버리지는 99.9% 임.

채널 판정 — 3순위

순위근거예
①내원동기(중)에 매체명이 직접 적힌 경우모두닥 · 카페 · 크리에이트립 · 에이젼시(외국)→해외에이전시 · 강남언니/바비톡→기타플랫폼
②직원 설정표(reservation_channel_staff)자사 해외 등 — DB 로 관리해 코드 수정 없이 늘림
③예약 경로인콜 · 아웃콜 · 홈페이지 · 앱 · 네이버

판정은 뷰가 하고 화면은 하지 않음. 규칙을 바꾸려면 v_reservation_channel 만 고치면 이 화면과 채널별 수익성이 함께 따라옴.

재수술은 코호트 기준임

"그 달에 예약한 사람이 나중에 재수술까지 갔나"를 셈. "그 달에 재수술한 사람"이 아님. 재수술은 원수술 몇 달~몇 년 뒤에 일어나는데 원천이 2026-01 부터라 최근 코호트일수록 0 임(2026-01 코호트 3명, 07 코호트 0명). 정상이며 데이터가 쌓일수록 채워짐.

컬럼 정의 — 퍼널 표 13개
