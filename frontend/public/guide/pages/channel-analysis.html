개요 — 이 화면은 무엇인가

유입 채널별로 고객이 누구이고 객단가가 왜 그런지 정리한 분석 문서 모음임. 좌측에서 채널을 고르면 해당 문서가 열립니다. 실측 기준이며 화면은 조회를 하지 않음(수치는 본문에 고정).

2

사용자와 쓰임새

숫자가 아니라 결론을 담는 화면

퍼널과 수익성이 채널이 지금 어떤 숫자인지를 보여준다면, 이 화면은 그 숫자를 어떻게 읽어야 하는지를 담음. 채널마다 고객이 누구이고 객단가가 왜 그런지를 실측으로 검증한 분석 문서 10편임.

왜 조회를 하지 않는가

본문 수치는 실측 시점의 값을 고정했음. 매달 갱신되는 화면으로 만들면 숫자만 바뀌고 결론의 근거가 사라짐 — "그때 이 숫자를 보고 이렇게 판단했다"가 남지 않음. 이 화면의 값어치는 어떤 가설이 검증되고 어떤 가설이 죽었는지에 있음. 최신 수치는 예약 퍼널·채널별 수익성이 담당함.

쓰는 장면하는 일
채널 판단 근거 확인"모두닥은 왜 객단가가 낮은가" 같은 물음의 검증 결과를 봄
신규 인력 온보딩채널마다 무엇이 다른지 한 번에 읽힘
가설 재검토죽은 가설을 다시 꺼내지 않게 함

4

조회 조건과 필터

조회 조건이 없음

기간·필터가 없음. 정적 문서 모음이라 고를 것이 채널 하나뿐임.

항목동작
채널 선택좌측 목록. 문서 전환만 함
기간없음 — 본문 수치는 실측 시점 고정
추세 차트일부 채널에서만, 문서가 정한 범위로 자체 조회
본문 숫자에는 기준 시점이 붙어 있어야 함

고정값이므로 "언제 기준인지"가 문서 안에 없으면 읽을 수 없음. 새 채널 문서를 쓸 때 반드시 실측 기간을 명시함.

문서 한 편이 답해야 할 것

물음왜 필요한가
누가 오는가연령·직업·지역 구성. 객단가 차이의 절반은 여기서 설명됨
객단가가 왜 그런가시술 구성·렌즈 비중으로 설명함. "채널이 나쁘다"와 "고객군이 다르다"는 다른 말임
검증된 가설 / 죽은 가설이 화면의 핵심. 같은 논의를 반복하지 않게 함
실측 기간고정값이라 시점이 없으면 못 읽음
이 화면은 상태가 complete 임

조회가 없는 정적 문서인데도 미구현이 아님 — 수치가 본문에 박혀 있어 API 없이 완결이기 때문임. 구현 상태는 "화면이 제 역할을 하는가"를 뜻하지 "API 가 붙었는가"가 아님.

컬럼 정의 — 모두닥 문서 월별 퍼널 차트 시리즈 7개

문서 10편은 정적이라 컬럼이 없고, 모두닥 문서의 월별 퍼널 차트만 조회함. 예약 퍼널 화면은 사람 수를, 이 차트는 건수를 써서 두 숫자가 다름.

#화면 라벨응답 필드마트 컬럼CRM 원천비고
1예약reservedreserved (COUNT(*))RESERVATION.InsertedDateTime 이 그 달인 모두닥 채널 예약 건모두닥 채널 = 내원동기(중)이 '모두닥'인 건
2취소 제외notCancelnot_cancelRESERVE_STATE <> 'C'—
3접수visitedvisitedRESERVE_STATE IN ('I','H')—
4검사examinedexamined그중 EXAM.EXAM_DATE 있음—
5중단 제외notStopnot_stop그중 EXAM.STOP_YN ≠ 'Y'—
6수술등록surgerysurgery그중 수술예약(RESERVE_FLAG='O') 등록일 있음—
7수술완료surgeryDonesurgery_done그중 실제 수술일(OPERATIONDATA) 있음재수술(reop)은 이 차트에 없음

컬럼 정의 — 「단계별 월 건수」 표 3개

차트 아래 표. 행 = 위 시리즈 7개, 열 = 1월~12월 + 합계.

1단계— (시리즈 라벨)——색 칩 + 라벨. 순서는 퍼널 순서
21월 ~ 12월월별 호출의 해당 시리즈 값——연도는 MODOODOC_FUNNEL_YEAR(2026) 고정. 도래하지 않은 달은 0
3합계— (프론트 합)——1~12월 전체 합. 건수 기준이라 사람 수 합계와 다름
