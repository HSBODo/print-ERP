2

사용자와 쓰임새

누가 여는가

수술 건수가 이룬 명단을 폄. 검사자 리스트와 짝이고 컬럼 구성도 거의 같지만, 기준 날짜가 수술일이고 수술방법·집도의·수납금액이 앞쪽에 옴.

쓰는 장면하는 일
총수술 대조「전체」 탭 조회건수가 월간 레포트 총수술과 같은지 봄
수술 유형 확인스마일·ICL·라섹계 등으로 좁혀 그 달 어떤 수술이 늘었는지 사람 단위로 봄
재수술 판정자동 판정이 애매한 건을 화면에서 직접 뒤집음 — 아래 참조
수납 확인견적가·수술가율·수납금액으로 실제 결제를 되짚음
이 화면만 데이터를 고칠 수 있음

다른 리스트는 전부 읽기 전용인데, 이 화면에는 재수술 판정을 저장하는 기능이 있음. 자동 판정(REASON_CD 기반)이 놓치거나 잘못 잡은 건을 사람이 뒤집어 저장하면, 그 판정이 자동 판정보다 우선함.

수술 유형은 '받은 사람' 기준임

한 사람이 좌우에 다른 수술을 받으면 통계는 대표유형 하나로 접지만, 이 리스트는 그 유형을 받은 사람이면 다 보여줌 (2026-07 ICL: 받은 사람 44명 / 대표유형 41명). 사람을 찾는 화면이라 그쪽이 자연스러움 — 그래서 유형별 건수를 더해도 전체와 안 맞음. 통계로 쓰면 안 됨.

4

조회 조건과 필터

서버 조회는 기간 + 탭 두 가지

조건어디서규칙
기간서버GET /api/surgery-list?from&to — 기준은 수술일
수술구분 = 재수술서버GET /api/stats/surgery/reoperation-candidates — 다른 테이블임
수술구분 = 전체서버 둘 다수술자 리스트 + 재수술 후보를 합쳐 수술일 순으로 정렬
유형·옵션·렌즈·재수술종류화면수술명 문자열을 분류 함수에 넣어 판정
검색어화면고객명 · 차트번호 · 휴대전화
재수술은 다른 테이블에 있음

재수술은 RE_OPERATION 에 따로 기록돼 OPERATIONDATA·Cataract_Operationdata 기반 수술자 리스트에 들어 있지 않음. 그래서 탭을 바꾸면 호출하는 API 자체가 달라짐.

표 · 지표 정의

모집단 — 세 원천을 탭으로 나눔

탭원천단위
시력교정OPERATIONDATA고객 × 수술일
백내장Cataract_Operationdata고객 × 수술일 (좌·우가 각각 날짜를 가짐)
재수술RE_OPERATION자동 포함 판정된 건만
전체위 셋을 더함월간 레포트 총수술과 같은 가산 기준
불변식 — 전체 탭 = 레포트 총수술

2026-07 기준 726(시력교정) + 43(백내장) + 29(재수술) = 798 = 레포트 총수술. 같은 사람·같은 날이 수술자 리스트와 재수술에 함께 잡히는 건이 있지만 (2026-07 6건 — 렌즈 제거+삽입처럼 한 세션이 두 테이블에 각각 기록된 경우), 레포트도 같은 방식으로 더하므로 여기서 걷어내지 않음. 일부러 남긴 중복임.

사람이 뒤집은 판정이 이김

저장된 판정의 키는 (차트번호, 수술일, 우안 시술명, 좌안 시술명) 네 개임. 같은 사람이 같은 날 시술명이 다른 재수술을 받으면 별건으로 구분하기 위해서임. 저장이 없으면 자동 판정을 그대로 씀.
