개요 — 이 화면은 무엇인가

사용자 계정 CRUD (신규 · 편집 · 삭제). ADMIN 롤 전용. 자기 자신의 롤·부서는 변경할 수 없고, 마지막 ADMIN 은 삭제할 수 없다.

2

사용자와 쓰임새

화면이 아니라 도구임

대시보드에 로그인할 계정을 만들고 고치고 지우는 화면임. 지표는 없음. ADMIN 롤(개발자)만 열 수 있고, 다른 롤은 사이드바에도 보이지 않으며 API 도 403 임.

쓰는 장면하는 일
입사 · 신규 사용자아이디·이름·이메일·권한·부서·초기 비밀번호를 넣어 계정을 만들고, 아이디와 초기 비밀번호를 본인에게 전달함
부서 이동 · 승진권한(롤)이나 부서를 바꿈. 마케팅 → 메디컬처럼 보이는 메뉴 자체가 바뀜
비밀번호 분실편집 창에서 새 비밀번호를 넣어 초기화함. 사용자가 스스로 바꾸는 화면은 없음(10장)
퇴사계정을 삭제함. 되돌릴 수 없음

이 화면이 대체한 것

권한 2축(롤 × 부서)을 도입하기 전에는 계정이 ADMIN/USER 둘뿐이라 개발자가 DB 에 직접 넣었음. 부서별로 보이는 메뉴가 갈리면서(메디컬 · 마케팅 · 해외마케팅) 계정 하나에 정할 것이 늘어, 조합 규칙을 화면이 검사하게 했음. 초기 ADMIN 한 명은 앱 기동 시 환경변수로 만들어지고(DataInitializer), 그 뒤부터는 이 화면이 유일한 입구임.

⚠️ 자기 자신에게는 손대지 못하게 막아 둠

로그인한 관리자 본인의 롤·부서 변경과 삭제는 서버가 400 으로 거절함(자기 롤을 STAFF 로 낮추면 그 자리에서 잠김). 마지막 ADMIN 도 지울 수 없음 — ADMIN 이 0명이 되면 정책 조작이 완전히 막히기 때문임.

조회 조건과 필터

조회 기간 개념이 없는 화면임. 목록은 GET /api/admin/users 로 전체를 한 번에 받고, 검색·필터·페이지는 전부 화면에서 함.

조건어디서규칙
검색어화면아이디 · 이름 · 이메일 부분일치(대소문자 무시)
권한화면ADMIN · DIRECTOR · MANAGER · STAFF 중 하나
부서화면ALL · MEDICAL · MARKETING · OVERSEAS_MARKETING 중 하나
쓰기서버POST /api/admin/users · PUT /api/admin/users/{id} · DELETE /api/admin/users/{id}. 저장 뒤 목록을 다시 받음

사용자 수가 수십 명 규모라 서버 페이지네이션·서버 검색은 두지 않았음. 늘어나면 그때 옮김.

계정 목록 표

앱 DB(Postgres) 의 users 테이블을 JPA 로 읽음(GET /api/admin/users · 응답 UserRow). 마트도 CRM 도 거치지 않으므로 「마트 컬럼」 칸에는 users 컬럼을 적고 CRM 원천은 비움. password(BCrypt 해시)는 응답에 실리지 않음. 목록은 한 번에 전부 받고 검색(아이디 · 이름 · 이메일 부분일치) · 권한 · 부서 필터 · 페이지(20 · 50 · 100)는 화면에서 처리함.
