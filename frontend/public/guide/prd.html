제품 요약

비앤빛 Analytics 주요 지표 대시보드

제품 목표

비앤빛 안과 병원 경영진이 주요 지표를 한눈에 파악하고, 현장의 수기 및 엑셀 기반 비효율적인 데이터 집계 방식을 시스템화하여 데이터 기반의 의사결정을 강화하도록 지원함.

추진 배경

비앤빛 안과 내부에서 수기 및 엑셀로 관리되던 주요 운영 데이터를 시스템화하고 시각화하는 플랫폼임.

문제 정의 및 해결 방안

사용자 문제

병원 경영진은 병원 운영의 주요 지표를 수동으로 집계하고 분석해야 하는 비효율성을 겪고 있으며, 정확하고 신속한 의사결정을 위한 통합된 데이터 지표가 부족함.

해결 방안

비앤빛 Analytics 대시보드는 병원 운영의 주요 지표를 시각화하여 제공하고, 수기 및 엑셀 작업을 대체하여 데이터 집계의 정확성과 효율성을 높임. 지표는 매일 03시 배치가 갱신하는 T-1(전일) 기준이며, 지표 확인 용도에는 실시간성이 필요하지 않다는 판단에 따른 설계임.

핵심 차별화 요소

일반적인 BI 툴과 달리, 비앤빛 안과에 특화된 주요 지표와 운영 데이터를 맞춤형으로 제공하여 병원 현장의 특수성을 반영함. 기존의 분산된 수동 데이터 관리 방식에서 벗어나 통합적이고 자동화된 데이터 분석 환경을 구축하여 데이터 기반의 전략 수립을 지원함.

대상 사용자 및 활용 시나리오

대상 사용자

비앤빛 안과의 경영진 및 관리자. 이들은 병원 운영의 전반적인 성과를 파악하고, 효율적인 자원 배분 및 전략적 의사결정을 담당함. 정기적으로 병원 실적을 검토하고 개선점을 찾아야 하는 역할을 수행함.

주요 활용 시나리오

주간 경영 회의를 앞둔 병원 관리자 '김팀장'은 지난주 병원 운영 성과를 파악하기 위해 비앤빛 Analytics 대시보드에 접속함. 대시보드에서 수술 건수, 매출, 예약, 신규 환자 등 주요 지표를 한 화면에서 확인하고, 월별 추이 변화를 시각화된 차트를 통해 빠르게 분석함. 이 데이터를 바탕으로 회의에 필요한 보고서를 준비하고, 개선이 필요한 영역을 파악하여 다음 주 계획을 수립함.

주요 지표 및 리스크

주요 지표

이 제품의 성패는 얼마나 쓰이는가보다 숫자가 맞는가에 달려 있음. 그래서 성공 지표도 사용량이 아니라 정합성·적시성으로 잡음.

  • 정합성 — 리스트 합계 = 지표 = 레포트가 성립하는가. 명단 화면과 집계 화면이 같은 수를 말해야 함. 예: 전체 검사자 리스트 「전체」 = 월별 검사자 종합지표 총검사자, 수술자 리스트 「전체」 탭 = 월간 레포트 총수술(2026-07 실측 726+43+29 = 798), 예약자 리스트 행 수 = 예약 종합. 이 불변식이 깨지면 나머지 지표를 믿을 수 없음.
  • 적시성 — 아침에 열면 어제까지가 들어와 있는가. 화면은 마트만 조회하므로 적재가 밀리면 전 화면이 한꺼번에 낡음. 매일 03시 배치와 실행 이력·Slack 알림으로 지킴.
  • 수기 대체 — 엑셀로 만들던 산출물을 화면에서 뽑는가. 월간·주차 레포트 31개 도표가 대상임. PDF 로 저장해 그대로 회의에 들어가는 것이 완료 기준임.
  • 정의 문서화 — 화면과 지표의 기준이 글로 남아 있는가. 정의가 사람 머릿속에만 있으면 재정의가 반복됨. 2026-08 기준 메뉴 48종 중 35종의 기획서를 작성했고, 지표 정의는 환자 흐름별 6문서로 분리해 둠.

주요 리스크

  • 정의의 재현과 다중화 — 가장 큰 리스크. 병원 수기·엑셀과 숫자를 맞추는 과정에서 집계 단위(사람/눈/건)와 날짜 기준(검사일/예약일/등록일)이 지표마다 달라 재정의가 반복됐음. 더 어려운 것은 같은 이름이 여러 정의를 갖는 것임 — 원데이 판정 3벌, 주차 개념 3종(ISO 연간 주차 · 그 달의 주차 · 월), 예약통계의 '예약율' 6개. 이름만 보고 비교하면 틀림.
  • 스냅샷 드리프트. 원천 테이블이 고객당 1행을 덮어쓰는 구조라 과거 월 수치가 사후에 변동함. 주간 승인 + 월 마감 스냅샷 방침으로 대응 예정임.
  • 소급 입력 누락. 일일 배치는 D-1 하루치만 읽음. 월 1일 03:30 보정이 전월 전체를 재계산하므로 다음 달 1일 전에 들어온 늦은 입력은 흡수되지만, 그보다 늦게 입력되면 그 날짜를 다시 읽는 배치가 없어 영구 누락됨. 관리자 화면의 수동 재적재로만 복구됨.
  • 수기 입력 의존. 콜·TM·메신저 문의는 시스템에 기록이 남지 않아 담당자가 셀에 직접 넣음(예약통계 2종 · 해외 예약통계). 광고비와 렌즈 단가도 화면 입력임. 넣지 않으면 지표가 조용히 비어 있음.
  • 광고 성과 귀속 불가. 유료 클릭을 증명할 식별자(UTM · 클릭 ID · 광고 전용 번호)가 어느 매체에도 없어 ROAS 가 전부 추정임. 네이버 검색광고는 유입이 여러 채널로 흩어져 산출 자체를 보류하고 비용만 기록함.
  • 판정 규칙의 이중 구현. 수술 유형 분류가 프론트 classifyVision() 과 마트 함수 surgery_op_type() 두 곳에 살아 있어 한쪽만 고치면 조용히 어긋남. 새 시술이 들어오면 양쪽을 함께 늘려야 함.
  • 개인정보 접근 통제. 마트에 주민번호·연락처·주소를 복제함. 검사자 리스트 계열은 ADMIN 전용으로 막았으나 CSV 는 마스킹만 걸고 파일로 나감.
종전 리스크였던 MSSQL 읽기 전용에 따른 부하·실시간성 제약은 마트 전환으로 해소됐음. SSH 터널이나 VPN 이 끊겨도 화면은 마지막 적재분으로 동작함.

1차 목표

착수 시점의 1차 목표는 「월간 숫자를 맞춘다」 하나였음. 실제로 맞춰 보는 과정에서 두 번 넓어졌고, 매출을 붙이며 닫음. 범위가 늘어난 것이 아니라 같은 정합성 기준을 시간축(월 → 주)과 값축(건수 → 매출)으로 두 번 확장한 것임.

  1. 2026.06최초 정의
    주간 지표 자료를 기준으로 데이터를 추출, 환자 흐름 4단계의 월간 수치를 일치시킴

    병원이 이미 돌리고 있던 주간 지표 자료가 그때의 유일한 정답지였음. 그 자료가 무엇을 세고 무엇을 빼는지를 그대로 따라 데이터를 추출하고, 합산한 월간 수치가 예약 → 검사 → 수술 → 외래 네 단계에서 맞아떨어지는지를 1차 목표로 잡음. 이 네 개가 다른 모든 지표의 분모이기 때문임 — 여기가 틀리면 전환율·중단율·예약률·단가가 전부 함께 틀림.

    완료 기준 · 명단 화면 합계 = 종합 지표 = 월간 레포트. 세 자리에서 같은 수가 나올 것.

  2. 2026.071차 개정
    주차 단위를 추가함

    기준으로 삼은 자료가 주간인데 화면은 월간뿐이라, 대조하던 주기와 산출하는 주기가 어긋나 있었음. 월 단위로는 이미 지난 달만 설명할 수 있어 주간 회의 주기와도 맞지 않았음. 같은 네 지표를 주차 단위로 확장함. 이 과정에서 주차 개념이 세 가지(ISO 연간 주차 · 그 달의 주차 · 월)로 갈려 있음이 드러나, 도표마다 어느 정의를 쓰는지 명시하는 것을 요건에 함께 넣음.

    이때 레포트의 성격도 함께 바뀜 — 화면마다 따로 집계하던 것을, 추출한 명단(list_*)을 정본으로 두고 그 위에 얹은 뷰 페이지로 옮김. 명단과 레포트가 같은 행을 세게 되므로 숫자가 어긋날 자리 자체가 줄어듦.

    완료 기준 · 주차 레포트가 월간 레포트와 같은 정의 위에서 성립하고, 두 레포트가 모두 명단에서 파생될 것.

  3. 2026.082차 개정 · 종료
    매출을 결합해 1차 목표를 닫음

    건수만으로는 무엇이 좋아졌는지 답하지 못해 매출을 결합함. 같은 명단 위에 금액을 얹어 수술 유형별 단가와 구성비를 건수와 나란히 보게 됨.

    완료 기준 · 월간·주차 레포트를 화면에서 그대로 내려 회의에 사용. 이 시점으로 1차 목표를 닫고 이후 과제는 확장 전략으로 넘김.

작성 로드맵

작성 순서는 정의 문서 확보 여부를 기준으로 정한다. 정의 문서가 이미 있는 화면을 우선 이관하고, 정의가 확정되지 않은 화면은 후순위로 배치한다. 1·6·7·8·9장은 자동 생성되므로 수기 작성 범위는 2·3·4·5·10장이다.

1순위 — 5개

조회 빈도가 높은 명단 화면. 컬럼 정의가 기존 문서로 확보되어 이관 난이도가 낮다.

타 병원 적용 준비안

타 병원 적용에 필요한 준비 자료, 진행 순서, 담당 역할을 실무 기준으로 정리했습니다.

목차 01먼저 준비할 자료 02적용 절차와 데이터 연결 방식 03담당 역할과 준비·확인 자료
01

먼저 준비할 자료

아래 네 가지를 받으면 적용 범위와 연결 가능 여부를 확인할 수 있습니다.

준비 자료확인할 내용주 담당
기존 경영 보고서실제로 사용하는 월간·주간 보고서와 최근 확정 수치병원 운영 담당
데이터 항목과 샘플예약·검사·수술·외래·수납 항목, 상태 코드, 개인정보를 가린 샘플 데이터병원 전산 담당
주요 지표 기준기준 날짜, 집계 단위, 포함·제외 조건과 병원에서 확인하는 기준 수치병원 운영 담당 + 비앤빛
사용자와 권한사용자별 필요 메뉴, 개인정보 조회·다운로드 범위, 읽기 전용 접속 방법병원 책임자·전산 담당
먼저 할 일: 기존 보고서, 샘플 데이터, 기준 수치를 한 번에 받아 서로 맞는지 확인합니다. 이 자료가 확인되면 필요한 메뉴와 작업 범위를 정할 수 있습니다.
02

자료를 받은 뒤 이렇게 진행합니다

처음부터 전체 메뉴를 옮기지 않고, 필요한 범위부터 확인하고 연결합니다.

자료 확인

기존 보고서와 샘플 데이터로 필요한 항목이 있는지 확인합니다.

적용 범위 결정

예약·검사·수술·외래·리포트 중 먼저 사용할 메뉴를 정합니다.

주요 지표 기준 확정

기준 날짜, 집계 단위, 포함·제외 조건을 병원 담당자와 맞춥니다.

데이터 연결

병원 DB는 읽기 전용으로 조회하고, 연결 API를 통해 필요한 데이터만 공통 형식으로 전달합니다.

숫자 확인 후 사용

기존 보고서와 시스템 수치를 대조한 뒤 실제 경영회의에서 사용합니다.

권장 데이터 연결 방식

비앤빛 대시보드가 병원 운영 DB에 직접 접속하지 않고, 병원 내부의 연결 API 또는 연결 모듈이 필요한 데이터만 읽어 공통 형식으로 전달하는 구조를 권장합니다.

구분적용 방식
데이터 조회병원 DB에는 읽기 전용 계정으로 접속하고, 예약·검사·수술·외래·수납 중 합의한 항목만 조회합니다.
형식 변환병원마다 다른 테이블·항목·상태 코드는 연결 API에서 비앤빛의 공통 항목으로 변환합니다. 대시보드는 병원별 DB 구조와 관계없이 같은 방식으로 동작합니다.
데이터 전달병원 내부에서 비앤빛 API로 데이터를 전송하는 방식을 기본으로 합니다. 외부에서 병원 DB에 직접 접속하지 않아 보안 설정과 병원별 데이터 분리가 쉬워집니다.
수집 주기실시간 연결보다는 현재 운영 방식과 동일하게 매일 정해진 시간에 전일 데이터를 수집합니다. 필요한 경우 최근 기간을 다시 수집해 늦게 입력된 기록도 반영합니다.
보안·운영암호화 통신과 병원별 인증 정보를 사용하고, 필요한 개인정보만 전달합니다. 전송 건수·처리 시간·성공 여부를 기록하며 실패 시 재전송하고 누락·중복을 확인합니다.
적용 가능 판단: 필요한 항목을 읽을 수 있고, 주요 지표 기준과 담당자가 정해지며, 기존 보고서 수치와 대조할 수 있으면 적용을 시작할 수 있습니다.
03

담당 역할은 세 가지입니다

결정할 사람, 데이터를 설명할 사람, 연결하고 검증할 사람을 정합니다.

담당할 일준비·확인할 자료
병원 운영 책임자먼저 볼 메뉴와 주요 지표 기준, 사용자 권한을 결정기존 보고서·기준 수치·권한 목록
병원 전산 담당데이터 항목과 상태 코드를 설명하고 읽기 전용 접속을 지원데이터 항목표·코드표·샘플 데이터
비앤빛 담당자데이터를 연결하고 기존 수치와 대조해 차이를 정리연결 항목표·지표 기준표·수치 확인표
정리: 자료 4종과 담당 역할 3개가 준비되면 연결 가능 여부를 확인하고 적용 범위를 정할 수 있습니다. 첫 적용은 필요한 메뉴만 시작하고, 숫자가 맞는 것을 확인한 뒤 범위를 넓힙니다.
