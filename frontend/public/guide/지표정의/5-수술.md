# 지표정의 5 — 수술

> 환자 흐름(예약 → 검사 → 전환율/중단율 → **수술** → 외래)의 다섯 번째 단계.

## 한눈에 보기

**수술은 세 갈래로 나뉨.** 서로 다른 테이블에서 오고, 세는 단위도 다름.

| 구성 | 무엇인가 | 데이터 출처 | 날짜 기준 | 세는 단위 |
|---|---|---|---|---|
| **시력교정수술** | 라식·라섹·스마일·렌즈삽입 등 | `OPERATIONDATA` | `OPERATION_DATE` | **사람** |
| **백내장수술** | 백내장 인공수정체 수술 | `Cataract_Operationdata` | `OPERATIONR_DATE`<br>`OPERATIONL_DATE` | **눈** (좌/우 각각) |
| **재수술** | 이미 수술한 눈을 다시 수술 | `RE_OPERATION` | `REOP_DATE` | **건** |

> ⚠️ **단위가 다르므로 단순히 더하면 안 됨.** 시력교정은 사람, 백내장은 눈임.
> 총 수술수 = 시력교정 **사람** + 백내장 **눈** + 재수술 **건**
> (**2026-07 확정: 784 + 45 + 32 = 861**).

**화면 원칙 — 리스트 행은 「사람」, 표시 숫자는 「안」.**
수술자 리스트는 사람 목록이라 2026-06 에 62행이지만, 백내장 수술수는 65안이 맞음.

| 지표 | 집계식 |
|---|---|
| 시력교정 수술수 | 사람 × 수술일 |
| 백내장 수술수 | 안 |
| 재수술 | 건 |

> ⚠️ **현행 정의의 적용 구간은 2026-06 부터임.** 그 이전은 확정값으로 보호됨 —
> 2024·2025 와 2026-01~05 는 시드가 정본이라 **정의를 바꿔도 앞 구간 숫자는 움직이지 않음.**

**공통 규칙 — 세 갈래 모두 적용**

- 예약일이 아니라 **실제 수술한 날** 기준
- 고객명에 `테스트`·`test` 가 들어가면 제외
- 수술명이 비어 있거나 `X`·`OP불가`·`모든수술가능`·`op x`·`Strabismus`·`TEST-TEST` 면 제외

## 1. 시력교정수술

| 항목 | 내용 |
|---|---|
| **무엇을 세나** | 그 기간에 시력교정 수술을 실제로 받은 **사람 수** |
| **테이블** | `OPERATIONDATA` (고객당 1행) |
| **날짜** | `OPERATION_DATE` |
| **수술명** | `OPERATIONR`(오른눈) · `OPERATIONL`(왼눈) |
| **화면** | `/stats/surgery` 수술 건수 · `/stats/surgery-ratio` 주요 수술별 비중 |

### 수술 유형 10종

`OPERATIONR`/`OPERATIONL` 에 적힌 **수술명 문자열을 보고** 분류함.

| 유형 | 매칭 키워드 |
|---|---|
| 프레스비욘드 `presbyond` | `PRESBYOND` |
| 스마일프로 `smilePro` | `SMILE Pro` · `SMILEpro` · `SMILE PRO` |
| 스마일 `smile` | `SMILE` |
| 비바 `viva` | `VIVA` |
| T-ICL `tIcl` | `T-ICL` · `T-IPCL` · `T-GLAZE` · `T-ECHO` |
| ICL `icl` | `ICL` · `IPCL` · `ARF` · `ART` · `ARTIFLEX` · `GLAZE` · `ECHO` |
| T-KPL `tKpl` | `T-KPL` |
| KPL `kpl` | `KPL` |
| 라식 `lasik` | `FLAP LIFT` · `OPTI` · `iFS` · `VISU` · `fs200` · `Micro+` · `Hybrid` |
| 라섹 `lasek` | `EYECLE` · `T-prk` · `EYE CLE` · `EYE+` · `FLAP PRK` · `PtK` · `M-LE` |

> **위에서부터 순서대로** 판정함. `SMILE Pro` 가 `SMILE` 보다 먼저 걸리도록 **순서가 중요함.**
> `PRESBYOND` 를 맨 앞에 둔 이유는 `Mono+PRESBYOND` 처럼 섞여 들어와도 노안 시술로 잡기 위함임.
> 어디에도 안 걸리면 `other` 가 되고 유형별 집계에서 빠짐.

### ⚠️ PIOL 유형별은 「대표유형」 하나만 셈

**PIOL 5종(`icl`·`tIcl`·`kpl`·`tKpl`·`viva`)에만 적용되는 예외 규칙임.**

| | 규칙 |
|---|---|
| 대표유형 | **우안(`OPERATIONR`) 우선.** 우안에 PIOL 이 없으면 좌안 |
| 집계 단위 | 환자 × 집계버킷당 **한 유형에만** 1 |
| 적용 범위 | PIOL 5종만. 라식·라섹·스마일·부가옵션은 받은 항목마다 셈 |

**왜.** 양안에 서로 다른 렌즈를 넣는 경우가 흔함(오른눈 ICL · 왼눈 T-ICL).
받은 유형마다 세면 한 사람이 두 칸에 잡혀 **유형별 합이 실제 환자 수보다 커짐.**

> 그래서 **PIOL 만은 「유형별 합 = 합계」가 성립함**(2026-07 확정: 41+68+16+22+1 = 148).
> 아래 함정 ①의 예외임.

### 부가 옵션 5종 (유형과 별개로 중복 집계)

| 옵션 | 매칭 |
|---|---|
| 엑스트라 `xtra` | `+X` |
| 웨이브비전 `waveVision` | `W.V` |
| 모노비전 `monoVision` | `MONO` 로 시작 |
| 콘트라 `contra` | `CONT` |
| 퍼스널 `personal` | `P.E` |
| 라섹 EX500 / RED | `EYECLE` + `EX500` / `EYECLE` + `RED` |

## 2. 백내장수술

| 항목 | 내용 |
|---|---|
| **무엇을 세나** | 그 기간에 백내장 수술을 받은 **눈 수** |
| **테이블** | `Cataract_Operationdata` |
| **날짜** | `OPERATIONR_DATE`(오른눈) · `OPERATIONL_DATE`(왼눈) — **눈마다 날짜가 다름** |
| **단위** | 눈 = `고객번호 + 수술일 + R/L` 조합 |
| **화면** | `/stats/surgery` · `/stats/surgery-composition` |

> **왜 눈 단위인가** — 백내장은 좌우를 **다른 날 수술하는 경우가 많음.** 그래서 눈마다 수술일이
> 따로 있고, 레거시 백내장 수술건수도 눈 기준이라 그에 맞췄음.

### 인공수정체 3종

| 유형 | 매칭 키워드 |
|---|---|
| EDOF `catEdof` | `EDOF` · `Vivity` · `Eyhance` · `PureSee` · `Isopure` · `Symfony` |
| 다초점 `catMulti` | `Clareon` · `Panoptix` · `RESTOR` · `Lara` · `LISA` · `CTR(M)` · `CTRmulti` · `3PodF` · `T-CTR` · `T-CATARACT` · `Precizon` · `LAL` · `ELANA` · `Gemetric` |
| 단초점 `catMono` | `K-flex` · `Kflex` · **그 외 전부** |

> ⚠️ **단초점이 기본값임.** 새 다초점 렌즈명이 등장하면 조용히 단초점으로 잡힘.

> ✅ **`T-Clareon Vivity` 는 EDOF(프리미엄)임 — 2026-08-05 확정.**
> 이름에 `Clareon`(다초점)과 `Vivity`(EDOF)가 둘 다 들어 있어 순서에 따라 갈리는데,
> 의학적으로 Vivity 는 EDOF 이므로 **EDOF 를 먼저 보는 현재 순서가 맞음.**
> 레거시 월간보고에 맞추려고 순서를 뒤집지 말 것.

## 3. 재수술

| 항목 | 내용 |
|---|---|
| **무엇을 세나** | 이미 수술한 눈을 다시 수술한 **건수** |
| **테이블** | `RE_OPERATION` |
| **날짜** | `REOP_DATE` |
| **단위** | 건 (한 행 = 1건, 좌우 합쳐 1건) |
| **화면** | `/stats/reoperation-rate` 재수술율 — **미구현** |

### 레이저 / 렌즈 2종

| 유형 | 매칭 키워드 |
|---|---|
| 렌즈 `reopLens` | `remo` · `exch` · `ICL` · `ARF` · `ART` · `EVO` · `ECHO` · `GLAZE` · `precizon` · `Lisa` · `Gemetric` · `encla` |
| 레이저 `reopLaser` | 그 외 전부 |

### 재수술로 세지 않는 것

| 제외 대상 | 이유 |
|---|---|
| `Irrigation%` | 세척 — 재수술 아님 |
| `repo%` · `%reposition%` | 렌즈 위치 조정 — 재수술 아님 |
| `Clareon%` · `T-Clareon%` · `Tecnis%` · `LAL%` · `ELANA%` | 백내장 인공수정체 — 백내장 수술로 집계 |

### ✅ 사유코드(`REASON_CD`) 기반 판정 — 2026-07-31 확정

시술명 문자열 대신 **사유코드**로 판정함(`01`·`07`·`10` 제외). 다만 사유코드에도 오입력이 있어
**시술명 `Irrigation` 보정을 함께** 씀 — 순수 코드 단독 판정이 아님.

**2026 확정값** — 01=32 · 02=33 · 03=18 · 04=19 · 05=23 · 06=17 · 07=31
(비교연도도 함께 재산출됨: 2024 = 205 · 2025 = 272)

## 4. 알아둬야 할 것

### ① 유형별 합계 ≠ 전체 인원 (단, PIOL 은 예외)

**양쪽 눈에 다른 수술을 할 수 있음.** 오른눈 스마일 · 왼눈 라섹이면 `smile` 에도 `lasek` 에도
1명씩 잡히지만 전체 인원은 1명임. **유형별 숫자를 더해서 전체와 맞추려 하면 안 됨.**

> **예외 — PIOL 5종.** 대표유형 하나에만 집계하므로 합이 성립함.
> 반대로 **PIOL 유형별 값은 「그 렌즈를 받은 사람 수」가 아님** — 양안에 다른 렌즈를 넣으면
> 우안 쪽에만 잡히므로 실제 시술 건수보다 작음(2026-07 ICL: 실제 44명 시술 / 대표유형 41명).

### ② 시력교정에서 백내장 고객이 통째로 빠짐

백내장 수술 이력 조건이 **기간 제한 없이** 걸려 있음.
2020년에 백내장 수술을 받은 분이 2026년에 시력교정 수술을 받아도 시력교정수술에 안 잡힘.

### ③ 수술명 문자열 매칭이라 신규 수술명에 취약함

세 갈래 모두 **수술명 텍스트를 훑어** 분류함. 새 수술명·새 렌즈명이 도입되면 조용히
`other`(시력교정)나 `단초점`(백내장)으로 흘러감. **신규 수술 도입 시 분류 목록 갱신이 필요함.**
