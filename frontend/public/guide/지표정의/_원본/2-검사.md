# 지표정의 2 — 검사

> 환자 흐름(예약 → **검사** → 전환율/중단율 → 수술 → 외래)의 두 번째 단계.
> **무엇으로 이루어지고, 데이터를 어디서 가져오는지**를 정리함.

> ✅ **레포트 = 검사자 리스트 (2026-08-05 확정).**
> 월간·주차 레포트의 **검사 유입 6종**과 **검사수·원데이·일반**은 각자 계산하지 않고
> **전체 검사자 리스트와 같은 모집단**에서 나옴. 화면 두 곳의 숫자가 어긋나면 버그임.
>
> | 항목 | 기준 |
> |---|---|
> | 유입(일반·고객소개·직원소개) · 직업(직장인·학생·기타) | 리스트의 `introType` · `jobBucket` 집계와 동일 |
> | 검사수 | 리스트 전체 행수 |
> | **원데이 + 일반 = 검사수** | 리스트의 `examType` 집계와 동일. 원데이는 시력교정(M/5)뿐 아니라 **백내장 원데이(진료구분 7·9)도 포함**함 |
>
> 2026-07 실측: 원데이 561 + 일반 643 = 1,204 = 검사수.
> **예외 — 백내장 검사수는 56임(102 아님).** 분류 `백내장`+`중단`만 세는 값이고,
> 나머지 46건(노안/FU·기타)은 **검사수 총계에만** 들어감. 그래서
> `시력교정 + 드림렌즈 + 백내장 ≠ 검사수` 인 것이 정상임.
>
> ⚠️ 원데이 정의를 고치면 **세 파일을 함께** 고쳐야 함 —
> `select-one-day-exam-count-monthly.sql`(레포트 원데이) · `select-one-day-daily.sql`(주차·종합지표) ·
> `select-all-exam-list.sql`(리스트). 한쪽만 고치면 다시 어긋남.
>
> ⚠️ **원데이 예약률의 분자는 시력교정 수술예약만** 셈. 분모(원데이)에 백내장 3건이 들어가
> 예약률이 소폭 낮아짐(2026-07: 86.6% → 86.1%). 백내장 수술예약을 분자에 넣는 건 별건임.

## 한눈에 보기

검사는 **세 종류**로 나뉨. 소스 테이블도 세는 단위도 다름.

| 구성 | 무엇인가 | 데이터 출처 | 날짜 기준 | 세는 단위 |
|---|---|---|---|---|
| **시력교정검사** | 라식·라섹·렌즈삽입 등을 위한 검사 | `EXAM` | `EXAM_DATE` | **사람** |
| **드림렌즈검사** | 각막굴절교정 렌즈 검사 | `EXAM` | `EXAM_DATE` | **사람** |
| **백내장검사** | 백내장 수술 전 검사 | `RESERVATION` (`H` 예약) | `RESERVE_DATE` | **사람** |

> ✅ **2026-07-23 이후 세 종류 모두 "사람" 단위로 통일**됐음. 백내장의 종전 눈(좌/우) 기준은 폐기.

**시력교정과 드림렌즈는 같은 테이블(`EXAM`)에서 나옴.** `EXAM`에는 검사 종류 컬럼이 없어서
**그날 예약으로 갈라냄.**

## 1. 시력교정검사 · 드림렌즈검사

| 항목 | 내용 |
|---|---|
| **테이블** | `EXAM` (⚠️ **고객당 1행** — 과거 검사 이력이 안 남음) |
| **날짜** | `EXAM_DATE` (char(10), `YYYY-MM-DD`) |
| **단위** | 사람 = `COUNT(DISTINCT CUST_NUM)` (행 수와 같음) |
| **측정값 필터** | **없음** — 측정값 미입력 검사도 포함 |
| **화면** | `/stats/exam-list` 검사자 리스트 · `/stats/examination` 시술별 |
| **쿼리** | [select-exam-list.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-exam-list.sql) · [select-vision-correction-monthly.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-vision-correction-monthly.sql) |

### 어떻게 갈라내나

```
EXAM 한 행
 └ 그날 렌즈센터(D) 예약만 있고 검사(M) 예약이 없다  →  드림렌즈
 └ 그 외 전부                                        →  시력교정
```

```sql
CASE WHEN visit.hasDreamlens = 1 AND visit.hasMedical = 0 THEN '드림렌즈'
     ELSE '시력교정' END
```

> ⚠️ **시력교정은 기본값(`ELSE`)임.** 드림렌즈가 아니면 전부 시력교정이 됨.
> 그래서 **외래(`F`)·백내장(`H`) 예약으로 와서 검사 기록만 생긴 건도 시력교정에 섞임** (월 3~4명).
> 명단과 대응 방안은 [시력교정-검사자-점검_2026-06~07.md](../../점검/시력교정-검사자_2026-06~07.md) 참조.

### 백내장 그림자 행 제외

같은 날 백내장 검사기록이 있으면서 `EXAM` 측정값이 **전부 비어 있으면** 제외함.
백내장 환자가 `EXAM`에 껍데기 행만 남기는 경우를 걸러내는 장치임.

```sql
AND NOT (
  EXISTS (SELECT 1 FROM Cataract_Exam ce WHERE ce.CUST_NUM=e.CUST_NUM AND ce.EXAM_DATE=e.EXAM_DATE)
  AND RIGHT01~30 · LEFT01~30 이 모두 비어 있음
)
```

## 2. 원데이(당일OP) / 일반 구분

시력교정검사는 다시 **원데이**와 **일반**으로 나뉨.

| 구분 | 조건 |
|---|---|
| **원데이** | 그날 **검사OP 예약**(`RESERVE_FLAG='M'`, `RESERVE_JINRYO='5'`, `STATE IN ('I','H')`)이 있고<br>`STOP_YN <> 'Y'` + `CANCEL_CD = ''` |
| **일반** | 시력교정검사 − 원데이 |

> **원데이 = 검사받은 그날 바로 수술까지 가는 코스.**
> 재수술 당일OP(`RESERVE_JINRYO='7'`, 검사OP(Re))는 **원데이에 포함하지 않음** (2026-07-29 결정).

### ⚠️ 같은 판정이 5곳에 흩어져 있음 — 바꾸려면 전부 함께

| 파일 | 쓰임 |
|---|---|
| [select-one-day-exam-count-monthly.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-one-day-exam-count-monthly.sql) | 원데이 검사 건수 |
| [select-monthly-vision-rates.sql](../../../backend/src/main/resources/sql/softcrm/consultation/select-monthly-vision-rates.sql) | 상담성공률 원데이/일반 분해 |
| [select-one-day-daily.sql](../../../backend/src/main/resources/sql/softcrm/overall/select-one-day-daily.sql) | 주간 종합지표 |
| [select-all-exam-list.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-all-exam-list.sql) | 전체 검사자 리스트 표시 |
| [select-demographics-daily.sql](../../../backend/src/main/resources/sql/softcrm/overall/select-demographics-daily.sql) | 검사수 분해 |

> **미반영 결정 사항** — 수술을 진행하지 못한 분(`STOP_YN='Y'`)도 원데이로 세기로 정해졌으나

## 3. 백내장검사

| 항목 | 내용 |
|---|---|
| **테이블** | `RESERVATION` (⚠️ `Cataract_Exam`이 **아님**) |
| **구분** | `RESERVE_FLAG = 'H'` |
| **날짜** | `RESERVE_DATE` |
| **단위** | 사람 |
| **화면** | `/stats/cataract-exam-list` · 월간 레포트 |
| **쿼리** | [select-cataract-monthly.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-cataract-monthly.sql) · [select-cataract-exam-list.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-cataract-exam-list.sql) |

### 조건

```sql
RESERVE_FLAG = 'H'
AND ISNULL(RESERVE_JINRYO,'') <> '3'      -- C_재검사 제외
AND ISNULL(RESERVE_SEQ, 0)    <> 3        -- 노안5진료실 제외
AND RESERVE_STATE NOT IN ('C','Y')        -- 취소·미내원 제외
AND EXISTS (EMPLOYEE E WHERE E.EMP_NUM = 고객.MY_OPTOMETRIST)   -- ★ 검안사 배정됨
AND ( 고객.MY_COUNSELOR = 'BS0808'                              -- 중단
   OR EXISTS (EMPLOYEE E WHERE E.EMP_NUM = 고객.MY_COUNSELOR) ) -- 백내장
```

### 담당자 배정 상태로 분류가 정해짐

**2026-08-05 개편**으로 리스트 모집단이 넓어지고 분류가 4종이 됐음.
담당자 필터는 **모집단을 거르는 데 쓰지 않고 분류 계산에만** 씀.

| 분류 | 검안사(`MY_OPTOMETRIST`) | 상담사(`MY_COUNSELOR`) | 검사수에 포함? | 2026-07 |
|---|---|---|---|---:|
| **백내장** | 배정 O | 배정 O | ✅ | 45 |
| **중단** | 배정 O | `BS0808`(미지정) | ✅ | 11 |
| **노안/FU** | 배정 X | `BS0808` | ❌ | 40 |
| **기타** | 그 외 | 그 외 | ❌ | 6 |

**건수 불변식 — 깨지면 레포트가 틀어짐**

```
월간 레포트 백내장 검사수 = '백내장' + '중단'   (2026-06 = 55 · 2026-07 = 56)
백내장 리스트 전체 행수    = 4분류 합계          (2026-06 = 115 · 2026-07 = 102)
```

> ⚠️ **종전 문서의 "2026-07 = 54"는 폐기값임.** 개편 전 모집단(56행)에서 나온 숫자이고,
> 현행 기준 실측은 **56**(45+11)임. 배경·검증은
> [인수인계_2026-08-05_백내장검사.md](../../점검/인수인계_2026-08-05_백내장검사.md) §2-4·§3 참조.

> ⚠️ **`MY_OPTOMETRIST IS NOT NULL`로 판정하면 안 됨.** 빈 문자열이 걸려 분류가 뒤집힘.
> 반드시 `EXISTS(EMPLOYEE)`로 볼 것.

## 4. 검사수(전체) — 세 종류 합산

`/stats/procedure-exam` 화면의 **검사수**는 세션 단위 합산임.

```
검사수(전체) = EXAM 행 수(시력교정 + 드림렌즈) + 백내장 세션 수
```

## 5. 알아둬야 할 함정

### ① `EXAM`은 고객당 1행임

`Cataract_Exam`과 달리 **누적되지 않음.** 같은 사람이 다시 검사받으면 **덮어씀.**
그래서 **"이전에 검사받은 적 있는지"를 `EXAM`으로 판정할 수 없음.**

### ② 검사 유형은 그날 예약을 봄

검사자 리스트의 `검사구분`(검사·검사OP·재검사·당일재검사 등)은
**그 검사일 당일의 검사 예약**에서 가져옴.

레거시는 **가장 최근 예약**(날짜 무관, 미래 예약 포함)을 봐서 서로 다름.
레거시 방식은 **미래 예약이 잡히면 지나간 달 숫자가 바뀜.**
자세한 비교는 [원데이-레거시-비교_2026-07.md](../../점검/원데이-레거시-비교_2026-07.md).

### ③ 화면마다 백내장 모집단이 달랐음 — ✅ 2026-08-05 해소

종전에는 세 화면이 서로 다른 모집단을 써서 2026-07 기준 **54 / 57 / 88** 세 숫자가 나왔음.

| 화면 | 종전 기준 | 종전 07 |
|---|---|---:|
| 백내장 검사자 리스트 · 월간 레포트 | H 예약 + 검안사 배정 | 54 |
| 전체 검사자 리스트 조회건수 | H 예약 + `JINRYO='1'`만 | 57 |
| 전체 검사자 리스트 검사수 뱃지 | `Cataract_Exam` 세션 | 88 |

**세 SQL 을 한 모집단으로 통일했음** — `select-cataract-exam-list.sql` ·
`select-all-exam-list.sql` · `fragments/fragment-exam-session-source.sql`.
`CataractExamListSqlResourceTest` 가 세 파일의 `CASE`·술어가 글자까지 같은지 강제하므로
**이 테스트를 지우면 재발함.**

> ⚠️ **`isCat` 이름이 파일마다 뜻이 다름.**
> `fragments/fragment-exam-session-source.sql` → 검사수 집계 대상(56) / `exam/select-all-exam-list.sql` → H 예약 행 전부(102).
> 레포트와 맞출 땐 `isCat` 말고 **`catClass IN ('백내장','중단')`** 을 쓸 것.
>
> 상세는 [인수인계_2026-08-05_백내장검사.md](../../점검/인수인계_2026-08-05_백내장검사.md) §3 변경 2·3.

### ④ 레거시 명단의 `검사일자`는 역대 최초 예약일임

조회 기간과 무관하게 **그 고객이 처음 백내장 검사를 예약한 날**이 찍힘.
그래서 **명단을 검사일자 기준으로 훑으면 재방문자가 통째로 빠짐.**

| | 검사수 | 신환 | 재방문 |
|---|---:|---:|---:|
| 2026-06 | 55 | 43 | **12** |
| 2026-07 | 54 | 46 | **8** |

*"명단 세어보니 43명인데 왜 55인가"* 는 여기서 생기는 착시임.

### ⑤ `visionExam`은 중단·취소를 거르지 않음

[select-vision-correction-monthly.sql](../../../backend/src/main/resources/sql/softcrm/exam/select-vision-correction-monthly.sql)에는
`STOP_YN`·`CANCEL_CD` 조건이 없음. 그래서 `일반 검사 = visionExam − 원데이` 계산에서
**수술 중단자가 일반 검사로 흘러듦.**
