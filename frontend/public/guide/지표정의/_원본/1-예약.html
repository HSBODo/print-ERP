지표정의 1 — 예약

환자 흐름(예약 → 검사 → 전환율/중단율 → 수술 → 외래)의 첫 단계. 무엇으로 이루어지고, 데이터를 어디서 가져오는지를 정리함.

한눈에 보기

예약은 모두 RESERVATION 한 테이블에서 나옴. RESERVE_FLAG로 종류가 갈림.

⚠️ 왜 예약일이 아니라 등록일인가 — 레거시 RSS 화면이 등록일로 집계함. 예약일로 세면 다음 달 예약이 이번 달에 섞여 차트와 어긋남(특히 2월 +20%). 등록일은 미래가 불가능해서 당월까지 자연스럽게 완결됨.

1. 무엇으로 이루어지나 — 채널 구조

예약 종합
├─ 콜      = 인콜(CTI) + 아웃콜(CRM)
└─ 온라인  = 홈페이지(ONLINE) + 앱(APP) + 네이버(NAVER)

RESERVE_PATH 값으로 구분함.

그룹RESERVE_PATH표시명
콜CTI인콜 (걸려온 전화)
CRM아웃콜 (건 전화)
온라인ONLINE홈페이지
APP앱
NAVER네이버
(거의 없음)KAKAO카카오 — 아래 §4 참조

두 그룹은 서로 배타적이라 콜 + 온라인 = 종합이 성립함.

⚠️ 콜에만 붙는 추가 제외 조건

콜은 B2B(군인) 단체예약·재검·중복을 뺌. 온라인은 빼지 않음.

-- 콜에만 적용
AND ISNULL(r.RESERVE_SEQ,'') NOT IN ('8','5')          -- 8=B2B(군인) 단체
AND ISNULL(r.COMMENT,'') NOT LIKE '%B2B(군인)%'
AND ISNULL(r.COMMENT,'') NOT LIKE '%재검%'
AND ISNULL(r.COMMENT,'') NOT LIKE '%중복%'
AND ISNULL(r.COMMENT,'') NOT LIKE '%시뮬%'
AND ISNULL(r.COMMENT,'') NOT LIKE '%차트있음%'

왜 콜에만? 군인 단체예약(월 ~80건)이 콜로만 들어옴. 온라인에 같은 제외를 걸면 과소 집계됨.

2. 집계 쿼리

SELECT YEAR(r.InsertedDateTime) AS yr, MONTH(r.InsertedDateTime) AS mo,
  COUNT(DISTINCT CASE WHEN (콜조건) OR r.RESERVE_PATH IN ('ONLINE','APP','NAVER')
                      THEN r.RESERVE_NUM END) AS 종합,
  COUNT(DISTINCT CASE WHEN r.RESERVE_PATH IN ('ONLINE','APP','NAVER')
                      THEN r.RESERVE_NUM END) AS 온라인,
  COUNT(DISTINCT CASE WHEN (콜조건) THEN r.RESERVE_NUM END) AS 콜
FROM RESERVATION r WITH(NOLOCK)
WHERE r.InsertedDateTime >= :from AND r.InsertedDateTime <= :to
  AND r.RESERVE_FLAG = 'M'
  AND r.RESERVE_JINRYO IN ('','5','6','7','24','25')
  AND NOT (r.CUST_NAME LIKE '%테스트%' OR r.CUST_NAME LIKE '%TEST%'
           OR r.CUST_NUM = '8888888888888')
GROUP BY YEAR(r.InsertedDateTime), MONTH(r.InsertedDateTime)

4. 알아둬야 할 함정

① 레거시 공식값은 완전 재현이 불가능함

원본 화면(uSTATISTICSD1 / LoadData1)은 여러 소스를 합침.

  • 콜센터 MySQL 인입콜 (OPENQUERY(EICN_MySQL,...))
  • CtiRptLst · DB_CUSTOM(TM) · 해피톡

우리 정의는 RESERVATION 경로 기반 근접 추정치임. 진짜 공식값이 필요하면 OPENQUERY(EICN_MySQL,...)로 인입콜까지 재현할 수 있음(우리 연결에서 작동함).

② 카카오는 사실상 안 잡힘

카카오는 해피톡 채널이라 RESERVATION에 거의 안 들어옴 (HappyTalk_Counsel_List 기준 ★신환 월 9~16건). 온라인 합계에 실질적으로 미포함이지만 레거시 차트도 마찬가지임.

③ 취소(STATE='C')를 빼지 말 것

취소를 제외하면 −376건으로 차트에서 오히려 멀어짐. 등록 시점 기준 집계라 취소 여부와 무관하게 셈.

④ 렌삽(JINRYO 24·25)은 신경 쓸 필요 없음

RESERVE_FLAG='M'에는 0건임. 진료구분 목록에 들어 있지만 실제로 안 걸림.

⑤ RSS 수기 테이블은 폐기됐음

네이버/카카오 수기 입력 테이블(OnLineReservation)은 1행(2024-07, 삭제)뿐, 인입콜 캐시(RSS)도 31행(2025-08~11)뿐임. 현재 네이버는 RESERVE_PATH='NAVER'로 통합됐음.
