# 기획서 생성기

상위 폴더의 `pages/*.html` 47장을 **레포 코드에서 뽑아** 만들고,
`prd.html` 의 **「전메뉴 현황」 탭 본문을 갈아끼운다.**
메뉴가 늘거나 API 가 바뀌면 문서를 고치지 말고 여기서 다시 생성한다.

이 문서 폴더는 **레포 밖에 있다.** 그래서 훑을 레포 경로를 위치로 유추할 수 없고,
[`config.json`](config.json) 의 `repoRoot` 로 지정한다(환경변수 `DASHBOARD_REPO` 가 있으면 그쪽이 우선).
경로가 틀리면 `scan.mjs` 가 그 자리에서 멈추고 무엇을 고쳐야 하는지 알려 준다.

```bash
cd _build
node scan.mjs                # 레포 코드 → spec-data.json
node render-metric-docs.mjs  # 지표정의·db·db/tables·점검·databatch 의 .md → 같은 폴더의 .html
node gen.mjs                 # spec-data.json + content/ → ../prd.html 마커 구간 치환 + ../pages/*.html
```

Node 18+ 면 된다. 의존성 없음.

## 참조 문서도 HTML 로 찍는다 — .md 로 넘어가지 않게

기획서에서 `.md` 를 그대로 걸면 브라우저가 원문 텍스트를 띄운다. 탭바도 좌측 목록도 없는
화면으로 튕겨 「안에서 본문만 바뀌는」 흐름이 거기서 끊긴다. 그래서 참조 문서 58장을
**같은 껍데기(탭바 + 좌측 목록)로 렌더**해 두고, 링크는 쓰기 직전에 `.html` 로 돌린다.

| 어디 | 무엇 |
|------|------|
| `render-metric-docs.mjs` 의 `FOLDERS` | 렌더할 폴더 목록 (지표정의 · db · db/tables · 점검 · databatch) |
| `gen.mjs` 의 `RENDERED_DIRS` | 링크를 `.html` 로 돌릴 폴더 — **위 `FOLDERS` 와 짝이다. 함께 고칠 것** |

덕분에 `content/*.mjs` 와 `RELATED` 에는 원래대로 `.md` 경로를 적으면 된다.
「지표 정의」 탭은 뷰가 아니라 `지표정의/1-예약.html` 로 바로 가는 링크다 —
prd.html 의 탭 처리기가 `button.tab` 만 잡는 이유가 이것이다(`<a>` 까지 잡으면 탭 전환이 죽는다).

## prd.html 은 통째로 다시 쓰지 않는다 — 마커 주입

`prd.html` 은 손으로 쓴 문서다(PRD · Features · User Flow · Wireframe · 완료 목표).
생성기는 그 안의 「전메뉴 현황」 탭(`#view-menus`)에 있는

```html
<!-- GEN:menu-status -->
…(생성된 현황: 주요 지표 · 범례 · 섹션별 메뉴 표 · 비노출 · 로드맵 · 문서 지도)…
<!-- /GEN:menu-status -->
```

구간**만** 새로 생성한 내용으로 치환한다. 마커 밖은 한 글자도 건드리지 않는다.
마커 두 줄이 지워져 있으면 **덮어쓰지 않고 에러로 멈춘다** — prd.html 을 지키는 안전장치이므로
마커를 복구한 뒤 다시 돌린다. 같은 입력으로 두 번 돌려도 결과는 같다(멱등).
예전에 따로 있던 `index.html` 인덱스는 이 탭으로 흡수돼 사라졌다.

## 두 단계로 나눈 이유

`scan.mjs` 가 틀리면 47장이 한꺼번에 틀린다. 중간 산출물 `spec-data.json` 을 남겨
**생성 전에 추출 결과부터 확인**할 수 있게 했다. 이 파일은 diff 가 읽히므로 커밋해 둔다 —
코드 변경이 문서의 어느 칸을 움직였는지 여기서 먼저 보인다.

## 무엇을 어디서 읽나

| 뽑는 것 | 원천 |
|---------|------|
| 메뉴 목록 · 라벨 · 경로 · 설명 | `frontend/src/config/statsPages.ts` |
| 구현 상태 · 사이드바 숨김 · ADMIN 전용 · 3단 트리 | `frontend/src/config/navigation.ts` |
| 화면 컴포넌트 | `frontend/src/pages/*/routes.ts` |
| 호출 API | 컴포넌트에서 시작한 import 그래프의 `api.get/post/...` 리터럴 |
| 백엔드 컨트롤러 | `@RequestMapping` 이 선언한 경로 중 **가장 긴 접두사**가 맞는 것 하나 |
| SQL 리소스 · 테이블 | 컨트롤러가 주입받는 `final` 필드를 따라가며 모은 `SqlLoader.load("sql/…")` |

## 추출이 못 하는 것 — 읽을 때 감안할 것

- **import 그래프는 실제 호출보다 넓다.** 페이지가 남의 도메인 훅을 하나만 써도
  그 훅이 닿는 API 가 전부 잡힌다. 화면 조각(대문자 시작)과 `useXxx` 만 따라가고
  소문자 util 모듈은 끊어 뒀지만, 그래도 넓게 나오는 화면이 있다
  (해외마케팅 3종은 API 배럴을 공유해 12개가 똑같이 잡힌다).
- **테이블 목록은 컨트롤러 의존 그래프 기준이다.** 공용 리포지터리 하나에 여러 화면의
  SQL 이 들어 있으면 이 화면이 쓰지 않는 테이블까지 섞인다. 각 문서 6장에 이 경고를 붙여 뒀다.
- **`mixed`(마트+CRM) 는 판정이 아니다.** 프로파일(`postgres-mart` / `mssql`) 분기일 수도,
  공용 리포지터리 경유일 수도 있다. 5장을 쓰면서 실제 경로를 확인해 줄이는 게 맞다.
- 마트/CRM 구분은 **테이블 이름 표기**로 가른다 — 전부 소문자면 마트(Postgres),
  대문자가 섞이면 CRM(MSSQL) 원천. 새 마트 테이블을 대문자로 만들면 이 구분이 깨진다.

## 손으로 쓰는 곳

생성기는 각 문서의 **1 · 6 · 7 · 8 · 9장**(개요 · 데이터 소스 · API · 권한 · 연관 문서)만 채운다.
**2 · 3 · 4 · 5 · 10장**은 사람 몫이고, 재생성해도 **덮어써진다** —
내용을 채운 문서는 생성 대상에서 빼야 한다.

빼는 방법: `gen.mjs` 의 `SPEC_DONE` 에 메뉴 ID 를 넣는다. 그러면 그 메뉴는
파일을 만들지 않고, 전메뉴 현황 표에서 **작성 완료**로 표시된다
(`sms-management` 가 이 방식으로 `../sms.html` 을 가리킨다).
`pages/<id>.html` 을 직접 채워 완성했다면 `specHref()` 도 함께 손봐야 한다.

## 편집 지점

| 바꾸고 싶은 것 | 위치 |
|----------------|------|
| 작성 우선순위(1~4순위) | `gen.mjs` 의 `TIERS` |
| 화면별 연관 문서 링크 | `gen.mjs` 의 `RELATED` |
| 각 장의 「채울 것」 질문 | `gen.mjs` 의 `TODO_PROMPTS` |
| 완성된 기획서 표시 | `gen.mjs` 의 `SPEC_DONE` · `specHref()` |
| 생성 날짜 | `gen.mjs` 의 `TODAY` |

`pages/*.html` 의 스타일은 `sms.html` 의 `<style>` 블록을 그대로 읽어 쓴다. 색·간격을 바꾸려면
`sms.html` 을 고치고 다시 생성하면 47장이 함께 따라온다.
prd.html 에 주입되는 「전메뉴 현황」 콘텐츠는 prd.html 자신의 `<style>`(`#view-menus` 로 한정)을 쓴다.
