# 지표정의 3 — 외래

> 환자 흐름(예약 → 검사 → 전환율/중단율 → 수술 → **외래**)의 마지막 단계.
> **무엇으로 이루어지고, 데이터를 어디서 가져오는지**를 정리한다.
> 수술은 [지표정의2.md](4-수술.md), 검증 이력·코드 반영 상태는 [지표정의.md](../db/지표정의.md) §4에 있다.

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| **무엇을 세나** | 그 기간에 외래로 **내원한 건수** |
| **테이블** | `RESERVATION` |
| **구분** | `RESERVE_FLAG = 'F'` (외래) |
| **날짜** | `RESERVE_DATE` (char(10), `YYYY-MM-DD`) |
| **상태** | `RESERVE_STATE IN ('I','H')` — 내원·완료만. 예약(`Y`)·취소(`C`) 제외 |
| **세는 단위** | **행 수** (`COUNT(*)`) — ⚠️ 사람 수가 아니다 |
| **화면** | `/stats/outpatient-count` (메뉴: 외래 > 외래수) |
| **쿼리** | [find-outpatient-count-monthly.sql](../../backend/src/main/resources/sql/outpatient/find-outpatient-count-monthly.sql) |

> ⚠️ **다른 지표와 단위가 다르다.** 검사·시력교정수술은 사람, 백내장수술은 눈, **외래는 행(건)** 이다.
> 한 사람이 한 달에 외래를 세 번 오면 **3건**으로 잡힌다.

## 1. 무엇으로 이루어지나 — 외래 진료구분

`RESERVE_FLAG='F'` 안에서 `RESERVE_JINRYO`로 세부 구분된다. **현재 집계는 이걸 구분하지 않고 전부 합산한다.**

실측 (2026-07-29 조사, 7월은 07-29까지)

| 코드 | 명칭 | 어떤 경우인가 | 6월 | 7월 |
|---|---|---|---:|---:|
| `1` | **수술후외래** | 수술 환자의 경과 관찰 | 2,223 | **2,114** |
| `6` | **OP FU** | 수술 직후 단기 추적(Follow-Up) | 697 | **755** |
| `4` | 옵토맵망막 | 망막 정밀검사 | 241 | 256 |
| `14` | 녹내장 FU | 녹내장 추적 관찰 | 118 | 159 |
| `2` | 일반외래 | 일반 진료 목적 내원 | 78 | 66 |
| (빈값) | (명칭 없음) | 진료구분 미입력 | 53 | 39 |
| `3` | 수술후망막 | 수술 후 망막 확인 | 30 | 28 |
| `16` | 녹내장 | 녹내장 진료 | 28 | 18 |
| `10` | IPL | 안구건조증 시술 | 11 | 10 |
| `7` | PRP | 자가혈청 시술 | 1 | 0 |
| | **합계** | | **3,480** | **3,445** |

> **외래의 83%가 수술 후 관리다.** 수술후외래(2,114) + OP FU(755) = 2,869 / 3,445.
> 외래수는 사실상 **수술 볼륨을 뒤따라가는 지표**로 읽는 것이 맞다.

> 코드·명칭은 `MEDICAL_SUB_CFG`(`RESERVE_FLAG='F'`)에서 온다. 세부 분해가 필요하면 아래 쿼리를 쓴다.

```sql
-- 외래 진료구분별 분해 (참고용, 현재 화면에는 없음)
SELECT ISNULL(r.RESERVE_JINRYO,'') AS jinryo, ms.SUB_NAME, COUNT(*) AS cnt
FROM RESERVATION r WITH(NOLOCK)
LEFT JOIN MEDICAL_SUB_CFG ms WITH(NOLOCK)
  ON ms.RESERVE_FLAG = 'F' AND ms.SUB_FLAG = ISNULL(r.RESERVE_JINRYO,'')
WHERE r.RESERVE_FLAG = 'F' AND r.RESERVE_STATE IN ('I','H')
  AND r.RESERVE_DATE >= :from AND r.RESERVE_DATE <= :to
GROUP BY ISNULL(r.RESERVE_JINRYO,''), ms.SUB_NAME
ORDER BY cnt DESC
```

## 2. 집계 쿼리

```sql
SELECT CAST(SUBSTRING(r.RESERVE_DATE, 1, 4) AS INT) AS yr,
       CAST(SUBSTRING(r.RESERVE_DATE, 6, 2) AS INT) AS mo,
       COUNT(*) AS cnt
FROM RESERVATION r WITH(NOLOCK)
WHERE r.RESERVE_DATE >= :from AND r.RESERVE_DATE <= :to
  AND r.RESERVE_FLAG = 'F'
  AND r.RESERVE_STATE IN ('I','H')
GROUP BY CAST(SUBSTRING(r.RESERVE_DATE, 1, 4) AS INT),
         CAST(SUBSTRING(r.RESERVE_DATE, 6, 2) AS INT)
ORDER BY yr, mo
```

**조건이 세 줄뿐이다.** 다른 지표와 달리 테스트 고객 제외·담당자 조건 같은 것이 없다.

## 3. 어느 값을 쓰나 — 연도별 처리가 다르다

| 기간 | 처리 | 이유 |
|---|---|---|
| **2024 ~ 2025** | **레거시 확정값 고정** | DB 재집계하지 않는다 |
| **2026 이후** | **DB 라이브 계산** | 운영 DB에서 매번 산출 |

|---:|--:|--:|--:|--:|--:|--:|--:|--:|--:|--:|--:|--:|
| 2024 | 5257 | 5080 | 4721 | 4133 | 4159 | 4092 | 4760 | 4720 | 3696 | 4201 | 3948 | 4711 |
| 2025 | 5389 | 5389 | 4933 | 4349 | 4451 | 4000 | 4275 | 4354 | 3332 | 3724 | 3639 | 4086 |

### 2026 검증 (레거시 대조)

| 월 | 레거시(참고) | DB 계산 | 차이 |
|---|--:|--:|--:|
| 01 | 4822 | 4831 | +9 |
| 02 | 4339 | 4344 | +5 |
| 03 | 4247 | 4251 | +4 |
| 04 | 3653 | 3658 | +5 |

DB가 레거시보다 **월 4~9건 높다.** 테스트 고객·예약번호·메모를 제외해도 거의 같아서,
레거시 출력 시점 이후 상태값이 바뀐 것으로 추정한다.
**공식 표시값은 레거시가 아니라 DB 라이브 값을 쓴다.**

## 4. 알아둬야 할 함정

### ① 사람 수가 아니라 건수다

동일인이 여러 번 외래를 오면 각각 1건으로 잡힌다. **"외래 환자 수"로 읽으면 안 된다.**
사람 수가 필요하면 `COUNT(DISTINCT CUST_NUM)`으로 별도 산출해야 한다.

### ② `RESERVE_JINRYO='3'`(수술후망막)을 전역에서 빼지 말 것

2025-02에 레거시 5,389 vs DB 5,673으로 **+284** 차이가 났다.
그 달 `RESERVE_JINRYO='3'`이 294건이라 원인처럼 보이지만,
**이 코드를 전역에서 제외하면 다른 월이 크게 틀어진다.**

참고로 2026-06·07의 `3`(수술후망막)은 월 28~30건에 불과하다. **2025-02가 유독 많았던 것**이라
그 달만의 사정으로 보인다. 2024~2025는 레거시 고정값을 쓰므로 화면 표시에는 영향이 없다.
**전역 제외 규칙으로 만들지 말 것.**

### ②-1 진료구분이 비어 있는 건이 월 40~50건 있다

`RESERVE_JINRYO`가 빈 값인 외래가 6월 53건 · 7월 39건이다. 현재는 전부 외래수에 포함된다.
분해 리포트를 만들 때 **"(미분류)" 항목이 생긴다**는 점을 감안할 것.

### ③ 외래 예약이 검사자 집계에 섞여 들어간다

외래(`F`) 예약으로 내원했는데 **검사 기록(`EXAM`)이 만들어지는 경우**가 있다.
이러면 시력교정 검사자로도 잡힌다 — 2026년 6·7월 기준 월 3~4명.

자세한 내역과 대상자 명단은 [시력교정-검사자-점검_2026-06~07.md](../점검/시력교정-검사자_2026-06~07.md) §2 참조.
**외래수 자체에는 영향이 없고, 검사자 수가 부풀려지는 방향이다.**

### ④ 백내장 외래는 별도 코드다

백내장 쪽 외래는 `RESERVE_FLAG='Z'`(백내장외래)로 따로 있다.
**현재 외래수에는 포함되지 않는다.** 합산이 필요하면 별도 합의가 필요하다.

## 남은 확인 사항

- **백내장외래(`Z`) 포함 여부** — 업무 판단 필요. 현재 외래수에는 안 들어간다.
- **진료구분별 분해 화면 필요 여부** — 데이터는 있으나 현재 화면은 총합만 보여준다.
  수술후외래·OP FU가 83%를 차지하므로, 나머지를 따로 보고 싶다면 분해가 의미 있다.
- **미분류(빈 진료구분) 월 40~50건** — 입력 누락인지 의도된 것인지 확인 필요.
