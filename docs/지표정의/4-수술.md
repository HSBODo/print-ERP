> 환자가 병원을 거치는 순서대로 지표를 정리한다. **각 지표가 무엇으로 이루어지고, 데이터를 어디서 가져오는지**를 한 장에서 볼 수 있게 하는 것이 목적이다.
> 세부 검증 이력·함정은 [지표정의.md](../db/지표정의.md)에 있다. 이 문서는 **구성과 출처** 위주다.

# §1. 수술

## 1-0. 한눈에 보기

**수술은 세 갈래로 나뉜다.** 서로 다른 테이블에서 오고, 세는 단위도 다르다.

| 구성 | 무엇인가 | 데이터 출처 | 날짜 기준 | 세는 단위 |
|---|---|---|---|---|
| **시력교정수술** | 라식·라섹·스마일·렌즈삽입 등 | `OPERATIONDATA` | `OPERATION_DATE` | **사람** |
| **백내장수술** | 백내장 인공수정체 수술 | `Cataract_Operationdata` | `OPERATIONR_DATE`<br>`OPERATIONL_DATE` | **눈** (좌/우 각각) |
| **재수술** | 이미 수술한 눈을 다시 수술 | `RE_OPERATION` | `REOP_DATE` | **건** |

> ⚠️ **단위가 다르므로 단순히 더하면 안 된다.** 시력교정은 사람, 백내장은 눈이다.
> 전체 수술건수 = 시력교정 **사람 수** + 백내장 **눈 수**로 정의되어 있다.

**공통 규칙 — 세 갈래 모두 적용**

- 예약일이 아니라 **실제 수술한 날** 기준
- 고객명에 `테스트`·`test`가 들어가면 제외
- 수술명이 비어 있거나 `X`·`OP불가`·`모든수술가능`·`op x`·`Strabismus`·`TEST-TEST`면 제외

## 1-1. 시력교정수술

| 항목 | 내용 |
|---|---|
| **무엇을 세나** | 그 기간에 시력교정 수술을 실제로 받은 **사람 수** |
| **테이블** | `OPERATIONDATA` (고객당 1행) |
| **날짜** | `OPERATION_DATE` |
| **수술명** | `OPERATIONR`(오른눈) · `OPERATIONL`(왼눈) |
| **단위** | 사람 = `COUNT(DISTINCT CUST_NUM)` |
| **화면** | `/stats/surgery` 수술 건수 · `/stats/surgery-ratio` 주요 수술별 비중 |
| **쿼리** | [find-vision-monthly-by-type.sql](../../backend/src/main/resources/sql/surgery/find-vision-monthly-by-type.sql) |

### 무엇으로 이루어지나 — 수술 유형 9종

`OPERATIONR`/`OPERATIONL`에 적힌 **수술명 문자열을 보고** 분류한다.

| 유형 | 매칭 키워드 |
|---|---|
| 스마일프로 `smilePro` | `SMILE Pro` · `SMILEpro` · `SMILE PRO` |
| 스마일 `smile` | `SMILE` |
| 비바 `viva` | `VIVA` |
| T-ICL `tIcl` | `T-ICL` · `T-IPCL` · `T-GLAZE` · `T-ECHO` |
| ICL `icl` | `ICL` · `IPCL` · `ARF` · `ART` · `ARTIFLEX` · `GLAZE` · `ECHO` |
| T-KPL `tKpl` | `T-KPL` |
| KPL `kpl` | `KPL` |
| 라식 `lasik` | `FLAP LIFT` · `OPTI` · `iFS` · `VISU` · `fs200` · `Micro+` · `Hybrid` |
| 라섹 `lasek` | `EYECLE` · `T-prk` · `EYE CLE` · `EYE+` · `FLAP PRK` · `PtK` · `M-LE` |

> **위에서부터 순서대로** 판정한다. `SMILE Pro`가 `SMILE`보다 먼저 걸리도록 순서가 중요하다.
> 어디에도 안 걸리면 `other`가 되고 유형별 집계에서 빠진다. **신규 수술명이 생기면 여기에 추가해야 한다.**

### 부가 옵션 5종 (유형과 별개로 중복 집계)

| 옵션 | 매칭 |
|---|---|
| 엑스트라 `xtra` | `+X` |
| 웨이브비전 `waveVision` | `W.V` |
| 모노비전 `monoVision` | `MONO`로 시작 |
| 콘트라 `contra` | `CONT` |
| 퍼스널 `personal` | `P.E` |
| 라섹 EX500 / RED | `EYECLE` + `EX500` / `EYECLE` + `RED` |

### 쿼리 (핵심만)

```sql
-- 좌우 눈을 UNION ALL 로 펼친 뒤 사람 단위로 DISTINCT
SELECT YEAR(op_date) AS yr, MONTH(op_date) AS mo,
       COUNT(DISTINCT CASE WHEN op_type='smile' THEN cust_num END) AS smile,
       -- ... 유형별 반복 ...
       COUNT(DISTINCT cust_num) AS visionPatients
FROM (
    SELECT o.OPERATION_DATE AS op_date, o.CUST_NUM AS cust_num,
           o.OPERATIONR AS raw, <위 분류 CASE> AS op_type
    FROM OPERATIONDATA o WITH(NOLOCK)
    LEFT JOIN CUSTOM cu WITH(NOLOCK) ON cu.CUST_NUM = o.CUST_NUM
    WHERE o.OPERATION_DATE >= :from AND o.OPERATION_DATE <= :to
      AND o.OPERATIONR IS NOT NULL AND RTRIM(o.OPERATIONR) <> ''
      AND o.OPERATIONR NOT IN ('X','OP불가','모든수술가능','op x','Strabismus','TEST-TEST')
      AND NOT EXISTS (SELECT 1 FROM Cataract_Operationdata co WITH(NOLOCK)
                      WHERE co.CUST_NUM = o.CUST_NUM)      -- ★ 백내장 고객 제외
      AND NOT (테스트 고객)
    UNION ALL
    <OPERATIONL 로 같은 블록 반복>
) e
GROUP BY YEAR(op_date), MONTH(op_date)
```

> ⚠️ **`NOT EXISTS Cataract_Operationdata`가 중요하다.** 백내장 수술 이력이 있는 고객은
> **기간과 무관하게 통째로 빠진다.** 백내장 수술을 받은 분이 나중에 시력교정 수술을 받아도 안 잡힌다.
> 백내장/시력교정 중복 집계를 막으려는 장치지만, 부작용이 있다는 점을 알고 있어야 한다.

## 1-2. 백내장수술

| 항목 | 내용 |
|---|---|
| **무엇을 세나** | 그 기간에 백내장 수술을 받은 **눈 수** |
| **테이블** | `Cataract_Operationdata` |
| **날짜** | `OPERATIONR_DATE`(오른눈) · `OPERATIONL_DATE`(왼눈) — **눈마다 날짜가 다르다** |
| **수술명** | `OPERATIONR` · `OPERATIONL` (인공수정체 종류) |
| **단위** | 눈 = `고객번호 + 수술일 + R/L` 조합 |
| **화면** | `/stats/surgery` · `/stats/surgery-composition` |
| **쿼리** | [find-cataract-monthly-by-type.sql](../../backend/src/main/resources/sql/surgery/find-cataract-monthly-by-type.sql) |

> **왜 눈 단위인가** — 백내장은 좌우를 **다른 날 수술하는 경우가 많다.** 그래서 눈마다 수술일이 따로 있고,
> 레거시 백내장 수술건수도 눈 기준이라 그에 맞췄다.

### 무엇으로 이루어지나 — 인공수정체 3종

| 유형 | 매칭 키워드 |
|---|---|
| EDOF `catEdof` | `EDOF` · `Vivity` · `Eyhance` · `PureSee` · `Isopure` · `Symfony` |
| 다초점 `catMulti` | `Clareon` · `Panoptix` · `RESTOR` · `Lara` · `LISA` · `CTR(M)` · `CTRmulti` · `3PodF` · `T-CTR` · `T-CATARACT` · `Precizon` · `LAL` · `ELANA` · `Gemetric` |
| 단초점 `catMono` | `K-flex` · `Kflex` · **그 외 전부** |

> ⚠️ **단초점이 기본값(`ELSE`)이다.** 새 다초점 렌즈명이 등장하면 조용히 단초점으로 잡힌다.
> 신제품 도입 시 목록 갱신이 필요하다.

### 쿼리 (핵심만)

```sql
SELECT YEAR(op_date) AS yr, MONTH(op_date) AS mo,
       COUNT(DISTINCT CASE WHEN cat_type='catMulti' THEN eye_key END) AS catMulti,
       COUNT(DISTINCT CASE WHEN cat_type='catMono'  THEN eye_key END) AS catMono,
       COUNT(DISTINCT CASE WHEN cat_type='catEdof'  THEN eye_key END) AS catEdof,
       COUNT(DISTINCT eye_key) AS cataractPatients
FROM (
    SELECT c.OPERATIONR_DATE AS op_date,
           LTRIM(RTRIM(c.CUST_NUM)) + '|' + c.OPERATIONR_DATE + '|R' AS eye_key,   -- ★ 눈 키
           <분류 CASE> AS cat_type
    FROM Cataract_Operationdata c WITH(NOLOCK)
    WHERE c.OPERATIONR_DATE >= :from AND c.OPERATIONR_DATE <= :to
      AND c.OPERATIONR IS NOT NULL AND RTRIM(c.OPERATIONR) <> ''
      AND c.OPERATIONR NOT IN ('X','OP불가','TEST-TEST')
      AND NOT (테스트 고객)
    UNION ALL
    <OPERATIONL / OPERATIONL_DATE 로 같은 블록 반복, eye_key 는 '|L'>
) e
GROUP BY YEAR(op_date), MONTH(op_date)
```

## 1-4. 알아둬야 할 함정

### ① 유형별 합계 ≠ 전체 인원

**양쪽 눈에 다른 수술을 할 수 있다.** 오른눈 스마일 · 왼눈 라섹이면 `smile`에도 `lasek`에도 1명씩 잡히지만
전체 인원(`visionPatients`)은 1명이다. **유형별 숫자를 더해서 전체와 맞추려 하면 안 된다.**

### ② 시력교정에서 백내장 고객이 통째로 빠진다

`NOT EXISTS Cataract_Operationdata`가 **기간 제한 없이** 걸려 있다.
2020년에 백내장 수술을 받은 분이 2026년에 시력교정 수술을 받아도 시력교정수술에 안 잡힌다.

### ③ 수술명 문자열 매칭이라 신규 수술명에 취약하다

세 갈래 모두 **수술명 텍스트를 `LIKE`로 훑어** 분류한다.
새 수술명·새 렌즈명이 도입되면 조용히 `other`(시력교정)나 `단초점`(백내장)으로 흘러간다.
**신규 수술 도입 시 분류 목록 갱신이 필요하다.**

### ④ 재수술 판정은 `REASON_CD`로 바꾸는 것이 맞다

`RE_OPERATION`에는 **정규화된 사유 컬럼 `REASON_CD`(char(3)) / `REOP_REASON`** 이 있고,
2025-01 이후 934건에 12종이 빠짐없이 채워져 있다.

`01 Irrigation` · `02 ENHANCE` · `03 Re-enclavation` · `04 Bioptics` · `06 Lens Removal` ·
`07 Lens Reposition` · `08 Lens Exchange` · `09 Keraring` · `10 CATARACT` ·
`12 RAINDROP Removal` · `13 Ingrowth Removal` · `16 enclavation`

**제외 3종(`01`·`07`·`10`) / 나머지 포함**으로 두면 기획 의도와 정확히 맞는다.

그런데 현재 쿼리는 이 컬럼을 안 쓰고 시술명 문자열로만 판정한다.
**2026-01~07 306건 중 8건(2.6%)이 어긋난다** — 잘못 제외 4건, 잘못 포함 4건.
**4건씩이라 월 합계는 우연히 상쇄되지만 개별 명단은 틀린다.** 총량만 보면 안 잡히는 종류의 오류다.

> 재수술 집계·명단 작업 시 문자열 패턴을 늘리지 말고 **`REASON_CD` 기반 전환을 먼저 검토할 것.**
> 단, 재수술 분류 기준은 **팀장 검증 대기** 상태이므로 기준 변경은 확인 후 착수한다.
