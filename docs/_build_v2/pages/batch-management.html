2

사용자와 쓰임새

화면이 아니라 도구임

지표를 보는 화면이 아니라 마트를 다시 채우는 도구임. 배치가 놓친 기간을 수동으로 재적재하고, 실행 이력을 확인함.

쓰는 장면하는 일
누락 복구늦게 입력된 과거 기록이 마트에 없을 때 그 기간을 다시 읽힘
정의 변경 반영SQL·분류 규칙을 고친 뒤 과거 구간을 다시 계산함
배치 실패 확인실행 이력에서 실패한 잡과 사유를 봄
초기 적재새 마트를 처음 채움
⚠️ ADMIN 전용 · 되돌릴 수 없음

재적재는 해당 기간을 지우고 다시 넣음(list 마트) 또는 덮어씀(monthly·daily 마트). 실행 전 상태로 되돌리는 기능은 없음.

언제 이 화면이 필요한가

일일 배치는 D-1 하루치만 읽고, 월 1일 보정은 전월 한 달만 다시 읽음. 그보다 더 과거로 뒤늦게 입력된 기록은 어떤 배치도 다시 읽지 않으므로 여기서 수동으로 재적재해야 함 (검사자 리스트 10장 참조).

화면 구성

실행 폼 + 이력 표. 두 덩어리뿐임.

배치 수동 실행
전체 도메인 재실행 ▾ 2026-07-01~2026-07-31 ▶ 실행
기간 내 전 도메인(수술·예약·검사·전환·외래·전체지표·기타)을 순차 재실행합니다. min-year 가드 우회.
실행 이력 ⟳ 새로고침
실행 유형잡대상 기간상태시작소요
▸MANUALorchestrator[ALL]2026-07-01 ~ 07-31성공08-26 09:124m 21s

이력 행을 펼치면 오류 상세가 나옴. 숫자는 예시임.

구성 요소

영역구성동작
도메인 선택전체 + 7개 도메인고르면 아래 설명이 바뀜

실행버튼동기 실행 — 끝날 때까지 기다림
이력표 + 펼치기실행 유형 · 잡 이름 · 기간 · 상태 · 소요시간 · 오류
도메인 설명을 화면에 적어 둠

"수술 도메인만"이 어느 마트를 건드리는지(mart_surgery_*) 화면이 직접 말함. 잘못 고르면 되돌릴 수 없으므로, 실행 전에 무엇이 바뀌는지 읽히게 했음.

4

조회 조건과 필터

조건어디서규칙
도메인서버ALL · SURGERY · RESERVATION · EXAM · CONSULTATION · OUTPATIENT · OVERALL · ETC
기간서버POST /api/admin/batch/rerun
이력서버GET /api/admin/batch/run-logs
수동 실행은 min-year 가드를 우회함

자동 배치는 대상 연도가 min-year(2026) 미만이면 건너뜀. 수동 실행은 그 가드를 일부러 우회함 — 초기 backfill 과 과거 보정에 필요하기 때문임. 그만큼 실수로 오래된 기간을 돌릴 수도 있음.
