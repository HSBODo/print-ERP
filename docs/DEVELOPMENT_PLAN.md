## 1. 비즈니스 개요

### 1.1 도메인
연포장(Flexible Packaging) 인쇄물 제조. PET·OPP·NY·LLDPE·AL(알루미늄) 등 **다층 복합 필름**을 합지하여 식품·음료·의약품용 **파우치/롤 포장재**를 생산한다.

### 1.2 공정 흐름 (실측 반영)

```
┌─ (원자재 압출/수입) ─▶ [압출]                 (자체 압출 소수)
│
수주 ─▶ (창고출고)
    │
    ├─ [인쇄]            ─ 당사 / 외주         ★ 4,935 건
    ├─ [코로나]          ─ 표면처리           30 건
    │
    ├─ [합지]            ─ 당사 / 외주         ★ 2,564 건 (별도 공정)
    ├─ [드라이]          ─ 논솔 / 솔벤 / 외주  ★ 960 건 (라미네이션 — 합지와 구분)
    ├─ [티다이]          ─ 외주               45 건 (합지 후 추가 코팅)
    │
    ├─ [슬리터]          ─ 상품용 / 원자재용    ★ 556 건
    ├─ [분단]            ─ 재단 후 분할        ★ 1,198 건
    │
    ├─ [가공]            ─ 외주 제대·실링      118 건
    │
    └─ [상품] 플래그      ─ 상품 재고 입고 경로  ★ 1,876 건 (공정이 아닐 가능성)
         │
         ▼
     출고 (차량배차)
```

- 수주마다 공정 경로가 다르다 (예: `인쇄` 단독 / `인쇄, 합지, 분단` / `인쇄, 드라이, 슬리터`).
- **"합지"와 "드라이"는 수주상 별도 토큰**: 단독 "합지"는 단층 비율 67%, 단독 "드라이"는 다층 97% → 실제 다른 공정으로 운용 중. v1에서 합쳐 본 것은 오류.
- **"상품"**은 공정이라기보다 **"상품 재고용 수주"를 표시하는 플래그**로 추정 (제품코드 500/200/480 접두사에 집중, 1,876건). → §11.3 결정 필요.
- 각 공정에는 당사/외주 구분이 존재하며, 외주는 발주서(작업지시서)를 그대로 전달.

### 1.3 현재 운영 방식의 한계
현행 운영은 **단일 엑셀 파일 1개**를 23개 시트로 나누어 수기 복사-붙여넣기로 수행 중이다.

| 현상 | 영향 |
|---|---|
| 수주 1건 입력 시 **5~6개 시트에 수작업 복사** (사용설명서 §2) | 누락·오타, 반영 지연 |
| 7,928건 누적된 **단일 수주 시트** | 열기/필터링 지연, 동시편집 충돌 |
| 압동로라·동판·원단 재고가 **셀 1칸** | 입출고 이력·소요량 추적 불가 |
| 외주 발주서·차량배차·품질체크 **분산** | 공정별 진척 추적 어렵고 월말 보고서 수기 집계 |
| **엑셀 수식 `#REF!` 다수** (창고출고·품질체크 시트) | 이미 깨진 집계 로직이 그대로 사용 중 |
| **공정 셀 자체에 오타 다수**(힌쇄·힙지·삼품·싱픔 등) | enum 정규화가 전환의 선결 과제 |
| **수주 공정 셀(10개+) ≠ 작업현황 공정 트래킹(5개)** 비대칭 | 운영 중에도 두 레이어가 어긋나 있음 |

**웹화의 핵심 가치**: ① "1회 입력 → 전 공정 자동 연계", ② 설비·자재 이력화, ③ 외주/배차/품질 통합 추적, ④ 실시간 집계 리포트.

| 분류 | 시트 | 비고 |
|---|---|---|

## 3. 핵심 데이터 모델

### 3.1 엔티티 개요 (ERD 축약)

```
Customer(고객)
Vendor(외주처)
Material(원단마스터) ──┐
                       ├── MaterialLot(원단 로트/재고)  ── MaterialMovement(입출고)
Plate(동판)            │
Roller(압동로라) ──  RollerPolishLog(연마 이력)
                       │
Product(제품마스터) ◀──┘  ← 원장
  · 제품코드, 재질구성(다층), 폭, 도수, 동판 FK, 기본 공정경로
      │
      ▼
Order(수주) ← 수주내역
  · LOT.NO, 수주일, 납기일, 작업량, 공정경로[], orderType(일반/상품재고), 비고
      │
      ├─▶ WorkOrder(공정별 작업지시)  — 1:N
      │     · process(ProcessType enum — §3.4)
      │     · 소속구분(IN_HOUSE/OUTSOURCE), 담당 Vendor, 예정일
      │     · 투입량, 생산량, 불량량(m), 수율(%), 특이사항     ← §3.5 KPI
      │     · 사용 Plate FK, 사용 Roller FK (공정별)
      │     · 상태 머신: PLANNED → RELEASED → IN_PROGRESS → DONE / HOLD / CANCELED
      │
      ├─▶ QualityCheck(품질확인)  — 공정별 N건
      │
      └─▶ Delivery(배차)         — 출고 시 N건
```

### 3.2 공정 경로 모델링 (수정됨)
수주내역의 `공정` 셀은 콤마 구분 문자열로 들어오고, 실측 결과 **65종 조합**에 **10개+ 공정 토큰**이 등장. 최상위 조합:

| 공정 조합 | 건수 |
|---|---:|
| `인쇄` | 2,321 |
| `상품` | 1,876 |
| `인쇄, 합지, 분단` | 864 |
| `인쇄, 합지` | 834 |
| `합지` | 474 |
| `인쇄, 드라이` | 315 |
| `합지, 분단` | 301 |
| `인쇄, 드라이, 슬리터` | 282 |
| `드라이` | 148 |
| `드라이, 슬리터` | 78 |

**적용 모델 (C안 유지 — 범위 확장)**:
- `Product.defaultProcessRoute` (JSONB) — 제품별 기본 공정 순서 템플릿
- `Order.processRoute` (JSONB) — 수주 시 복제 후 override
- 자유 토큰은 금지, **13개 enum + "기타"** 로만 선택 (오타 유입 차단)

### 3.3 LOT.NO 체계 (4가지 패턴 실측)

| 패턴 | 건수 | 예시 | 비중 |
|---|---:|---|---:|
| `YYMMDD-NNNN` | 3,991 | `230102-0001` | 50% |
| `CI{YYMM}-NNN` | 3,097 | `CI2610-055` | 39% |
| `YYMM-NNNN` 외 | 665 | `2301-3008`, `2309-4014` | 8% |
| `S{YYMM}-NNNN` 외 | 175 | `S2310-0001` | 2% |

**전환 전략**:
- **과거 데이터**: 원문 그대로 보존 (`lot_no` 컬럼에 varchar).
- **신규 LOT**: `CI{YYMM}-{NNNN}` 패턴으로 통일, DB 시퀀스로 월별 리셋.
- 과거 LOT 파싱 유틸은 `#shared/utils/lotParser.ts` 에 별도 분리 (4가지 모두 수용).

### 3.4 ProcessType Enum (13개 — 전면 확장)

| Enum | 공정 토큰 | 당사/외주 | 로라사용 | 비고 |
|---|---|---|:---:|---|
| `EXTRUSION` | 압출 | - | - | 필름 압출 (자체 or 수입) |
| `PRINT_IN` | 인쇄 (당사) | IN | ✅ | 당사 인쇄기 |
| `PRINT_OUT` | 인쇄 (외주) | OUT | - | 외주 인쇄 |
| `CORONA` | 코로나 | IN | - | 표면처리 (인쇄 전/후) |
| `LAMINATION_IN` | 합지 (당사) | IN | - | **드라이와 분리** |
| `LAMINATION_OUT` | 합지 (외주) | OUT | - | |
| `DRY_NONSOL_IN` | 드라이(논솔) | IN | ✅ | 당사 논솔 드라이 |
| `DRY_SOL_IN` | 드라이(솔벤) | IN | ✅ | 당사 솔벤 드라이 |
| `DRY_OUT` | 드라이(외주) | OUT | - | |
| `TDIE_OUT` | 티다이 | OUT | - | 합지 후 코팅 |
| `SLITTER_PROD` | 슬리터(상품) | IN | - | 상품용 재단 |
| `SLITTER_RAW` | 슬리터(원자재) | IN | - | 원자재용 재단 |
| `DIVISION` | 분단 | IN | - | 슬리터 후 분할 (1,198건) |
| `PACKAGING_OUT` | 가공 | OUT | - | 제대·실링 |
| `OTHER` | 타공·다공화·레이저칼선 등 | - | - | 희귀(<5건), 자유기재 |

**원칙**:
- 외주 공정(`*_OUT`)은 `vendorId` 필수.
- 로라 사용 공정은 `rollerId` 선택 (사용 이력 로깅).
- "상품"은 공정이 아니라 **`Order.orderType = 'RETAIL_STOCK'`** 플래그로 분리 (§11.3 결정 필요).

### 3.5 핵심 KPI 지표 (월말보고서 실측 기반 — 신규 섹션)

월말보고서는 공정별로 **4개 지표 + 월간 메타 2개** 를 집계한다. 데이터 모델에 전부 반영 필요.

| 지표 | 저장 위치 | 계산식 |
|---|---|---|
| **투입량(m)** | `WorkOrder.inputQuantity` | 공정 투입된 원자재/반제품 길이 |
| **생산량(m)** | `WorkOrder.outputQuantity` | 공정 산출 제품 길이 |
| **불량(m)** | `WorkOrder.defectQuantity` | 투입 - 생산 - 정상잔여 |
| **수율(%)** | `WorkOrder.yieldRate` (계산 컬럼) | `outputQuantity / inputQuantity * 100` |
| **근무일수** | `WorkOrder.workDays` 월별 집계 | 공정별 가동일수 |
| **12개월 롤링** | `MonthlyProductionSnapshot` | 월 마감 시 공정별 4지표 스냅샷 |

**월말보고서 추가 집계**:
- 전월잔량 / 당월 / 차월 수주량·건수 분리
- 공정별 작업건수 (근무일수와 별도)
- 당사/외주 매트릭스 (인쇄/외주인쇄/드라이/외주드라이/외주티다이/슬릿터 6개 축)

### 3.6 수주 공정 셀 ↔ 작업현황 공정 트래킹 비대칭 (신규 섹션)

현재 엑셀은 **두 레이어가 어긋나 있음**:

| 레이어 | 공정 범주 |
|---|---|
| 수주내역 "공정" 셀 | 10개+ (인쇄·합지·드라이·티다이·슬리터·가공·분단·코로나·압출·상품 등) |
| 작업현황 공정 트래킹 컬럼 | **5개** (인쇄·드라이·티다이·슬릿터·가공) |

**영향**: 수주에서 "인쇄, 합지, 분단" 으로 지정해도 작업현황에는 "합지·분단" 추적 컬럼이 없음 → 현장 운영이 **추적 밖에 놓인 공정들을 비공식 관리**.

**해결 방향**:
- 수주 공정 enum = 작업현황 공정 enum = **단일 ProcessType**(§3.4)로 통일
- "합지·분단" 전용 작업지시 큐도 웹에서 공식 추적
- 과거 데이터의 "상품" 토큰은 마이그레이션 시 `orderType` 플래그로 변환

### 3.7 결정 필요
- [ ] 공정 경로 모델 **C안** (제품 템플릿 + 수주 override) 확정?
- [ ] LOT.NO 신규 패턴 `CI{YYMM}-{NNNN}` 확정?
- [ ] **"상품" 토큰**은 공정이 아닌 `orderType` 플래그로 분리 — 승인?
- [ ] 동판·압동로라 바코드/시리얼 부여 여부

public List<WorkOrder> generateFromOrder(Order order) {

### 5.1 템플릿의 롤 × 부서 재활용
템플릿은 `ADMIN · DIRECTOR · MANAGER · STAFF` × 부서 조합. 공정별 담당자만 해당 공정 작업지시를 볼 수 있도록 **부서 = 공정 그룹**으로 운용.

|---|---|
| `DEPT_SALES` | 수주 등록·수정 전권 |
| `DEPT_PRINT` | `PRINT_IN`, `PRINT_OUT`, `CORONA` |
| `DEPT_LAMINATION` | `LAMINATION_IN`, `LAMINATION_OUT`, `DRY_*`, `TDIE_OUT` |
| `DEPT_SLITTER` | `SLITTER_PROD`, `SLITTER_RAW`, `DIVISION` |
| `DEPT_PACKAGING` | `PACKAGING_OUT`, `EXTRUSION` |
| `DEPT_WAREHOUSE` | 창고출고·원단 입출고 |
| `DEPT_LOGISTICS` | 차량배차 |
| `DEPT_QC` | 품질확인 전권 |
| `DEPT_ALL` | 생산관리·임원(전사 열람) |

## 6. 단계별 로드맵 (5단계, 각 4~6주 추정)

### Phase 0 · 데이터 클리닝 (신규 — v1 누락)
**목표**: 공정 토큰 정규화·마스터 중복 제거. 웹화 전 반드시 선행.

- 공정 셀 정규화: 65종 조합 → 13개 enum 매핑 사전 작성
  - 오타 매핑표: `삼품→상품`, `힌쇄→인쇄`, `힙지→합지`, `싱픔/상픔/싱품→상품`, `인쇄. 드라이→인쇄, 드라이` 등
  - 희귀 공정(코로나·압출·타공·다공화·레이저칼선)은 `OTHER` + 원문 보존
- 제품마스터(1,921건) 중복/거래종료 정리 → 영업부 검수
- 고객·외주처 마스터 명칭 통일 (약어·공백 차이)
- 산출물: `scripts/cleaning/normalize_process.py` + 정규화 매핑표 CSV
- **DoD**: 수주 7,928건 전체가 13개 enum + `OTHER` 로 100% 분류 가능.

### Phase 1 · 기반 (수주 자동화)
**목표**: "복사-붙여넣기" 1차 제거. 엑셀의 **수주내역 시트 대체**.

- 백엔드: `customer`, `vendor`, `material`, `product`, `order` 도메인 CRUD + REST Docs
- Flyway: `V2__create_customer.sql` ~ `V6__create_order.sql`
- 프론트:
  - 마스터 등록 화면 4개
  - 수주 등록/목록/상세 (`routes/_auth/order/`)
  - 제품 선택 시 재질구성·동판·**기본 공정경로** 자동 채움
  - 공정경로 멀티셀렉트 (13개 enum)
  - `orderType` 선택 (일반 / 상품재고)
- 이관: 원장 1,921건 + 최근 12개월 수주 CSV → ETL 스크립트
- **DoD**: 영업부가 신규 수주를 엑셀 대신 웹에서 입력하고 과거 제품 사양을 조회할 수 있다.

### Phase 2 · 공정 작업지시 (핵심)
**목표**: 수주 → 공정 WorkOrder 자동 생성. 공정별 **작업지시 PDF 출력** + **실적 입력**.

- 백엔드: `workorder` 도메인
  - 수주 생성 시 공정경로 기준으로 `WorkOrder` N건 자동 생성
  - 상태 머신 + **투입/생산/불량/수율** 4지표 입력
  - 작업지시 PDF (OpenPDF + Thymeleaf) — 현장용 인쇄본
- 프론트:
  - **공정별 큐 화면 9개** (print, corona, lamination, dry, tdie, slitter, division, packaging, extrusion)
  - 모바일/태블릿 친화 실적 입력 (투입량·생산량·불량·사진)
  - 간트 또는 캘린더 뷰 (예정일 기준)
- **DoD**: 수주 등록 → 공정 작업지시가 자동 생성되고, 공정 담당자가 당일 작업을 확인/실적 입력할 수 있다.

### Phase 3 · 재고/설비
**목표**: 원단·동판·로라를 이력화. 공정 투입 시 자동 차감.

- 백엔드: `material` 로트/입출고, `plate`, `roller` + 연마이력
  - 창고출고 요청 → 승인 → 출고 → 재고 차감 이력
  - 로라 사용/연마 트랜잭션
- 프론트:
  - 원단 재고 현황 (두께·폭별 매트릭스)
  - 동판 카드 뷰 (위치·상태 필터)
  - 로라 현황 (규격별 재고, 연마횟수·요청)
  - 저재고 알림 리스트
- **DoD**: 창고 담당자가 엑셀 창고출고 시트를 쓰지 않고, 재고 실시간 조회 + 소요량 추정이 가능하다.

### Phase 4 · 운영·리포트
**목표**: 품질·배차·대시보드·월말보고 자동화.

- 백엔드: `quality`, `delivery`, `report`
  - 월 마감 시 **공정별 KPI 4지표 스냅샷** 저장 (`MonthlyProductionSnapshot`)
  - **12개월 롤링 집계** API
- 프론트:
  - **작업현황 대시보드** (composition) — 엑셀 `작업현황` 대체, 공정별 색상 + 납기 임박
  - **월말실적보고서** (composition) — 엑셀 자동 집계 대체, PDF/엑셀 내보내기
    - 공정별 투입/생산/불량/수율/근무일수 + 12개월 롤링
    - 당사/외주 매트릭스 (인쇄·외주인쇄·드라이·외주드라이·외주티다이·슬릿터)
  - 품질확인 입력, 차량 배차 캘린더
- **DoD**: 월초 보고서 작성 시간 0, 공장장이 대시보드 1개로 그날 상황을 본다.

## 8. 기술적 고려사항

### 8.1 성능
- **수주 목록**: 1만 건 기준 — 서버 페이지네이션 + 인덱스(`(customer_id, delivery_date)`, `(lot_no)`).
- **작업현황 대시보드**: 공정 상태 조인이 많아짐 → 머터리얼라이즈드 뷰 또는 집계 테이블 고려.
- **12개월 롤링 리포트**: 월 마감 스냅샷 테이블로 조회 성능 확보.

### 8.2 PDF 출력
- 작업지시서 종이 출력이 현장 핵심. **OpenPDF + Thymeleaf 템플릿** 권장 (한글 폰트 패킹 필요).
- 공정별로 레이아웃 차이가 있을 수 있으므로 enum당 템플릿 1개를 전제.

### 8.3 모바일/태블릿
- 현장 공정 담당자는 PC 대신 태블릿 사용 가능성 → **실적 입력 화면만** 반응형 최우선. 마스터 CRUD는 데스크톱 전제.

### 8.4 테스트 전략
- 백엔드: `*DocsTest`가 OpenAPI 스펙 생성(템플릿 규칙). 도메인별 계약 테스트 필수.
- 프론트: Vitest + Storybook. 공정 상태 머신은 명세 기반 테스트.
- 공정 간 **상태 전이 시나리오**(수주→인쇄 완료→합지 투입→드라이 투입)는 통합 테스트로 보호.
- **공정 enum 매핑 정규화**는 Phase 0 산출물 CSV 를 입력으로 하는 재현 가능 테스트.

### 8.5 감사(Audit)
- 모든 작업지시 상태 변경과 재고 차감은 `BaseEntity`(생성/수정 자) + 별도 `audit_log` 테이블에 기록.
- 외주 발주/품질/재고는 책임 소재 이슈가 큼 → 로그 보존 **최소 3년**.

### 8.6 KPI 계산 정합성
- 수율(%) = `output/input * 100` — 하지만 월말보고서에는 **100%를 넘거나(과납) 음수 불량이 다수** 존재.
  → `yieldRate` 는 계산 컬럼이지만 UI 에서 100% 초과는 노란색 경고 표시.
  → 이 현상은 공정 간 재고 교차(이월 재공품)로 추정 → Phase 4 에서 "재공품(WIP)" 모델 재검토.
