## ① ② 785의 정체 — 장은애 1명 (저쪽 오분류)

7월 시력교정 대상에서 시술명에 `VIV`가 들어간 건은 **딱 둘뿐**이다.

| 차트 | 이름 | 수술일 | 우안 | 좌안 | 실제 |
|---|---|---|---|---|---|
| 2233224 | 장수미 | 2026-07-20 | `VIVA ICL` | `EVOp ICL` | **시력교정 VIVA** ✅ |
| 2208787 | 장은애 | 2026-07-10 | `T-Clareon **Vivity**` | `Clareon Pro` | **백내장 IOL** ❌ |

`Clareon Vivity`는 알콘 **백내장 인공수정체** 제품명이고, `VIVA ICL`은 시력교정 렌즈삽입술이다.
이름이 비슷할 뿐 전혀 다른 수술인데, 저쪽이 `Vivity`를 `VIVA`로 잡았다.

장은애는 `Cataract_Operationdata`에도 **우안 7/10 · 좌안 7/11**로 정상 등록돼 있는 백내장 환자다.

**이 한 사람이 세 지표를 동시에 +1씩 밀어 올렸다.**

| 지표 | 저쪽 | 실제 | 차이 |
|---|---:|---:|---|
| 시력교정 수술자 | 785 | **784** | 장은애 |
| VIVA | 2 | **1** | 장은애 |
| PIOL 환자 수 | 149 | **148** | 장은애 |

> 우리 SQL은 `NOT EXISTS (Cataract_Operationdata)` 로 백내장 이력자를 제외하므로 이 건이 걸러졌다.
> **저쪽 집계를 고쳐야 한다.**

### 784 검증 (운영 DB 실측)

| 구분 | 인원 |
|---|---:|
| `OPERATIONDATA` 7월 전체 (중복 없음) | 806 |
| − 백내장 이력으로 제외 | 22 |
| − 수술방법 제외키워드(`X`·`OP불가` 등) | 0 |
| − 테스트 계정 이름 | 0 |
| − CUSTOM 미매칭 | 0 |
| **= 우리 집계** | **784** |

제외된 22명은 **전원 실제 백내장 IOL 수술**이다(`Clareon` / `Clareon Pro` / `Clareon Vivity` /
`Tecnis Eyhance` / `Tecnis PureSee` / `K-flex`). 백내장 수술이 `OPERATIONDATA`에도 함께 기록돼
806에 섞여 들어온 것이며, 빼는 것이 맞다. 통계 화면과 수술자 리스트 SQL 모두 784로 일치한다.

> 참고 — 레거시(softcrm) 웹에는 **시력교정 수술자 명단 페이지가 없다**(백내장·B2B만 존재).
> 785는 레거시 화면 값이 아니라 별도 집계로 보인다.

## ③ 프레스비욘드 누락 (우리 문제)

7월에 프레스비욘드 수술을 받은 환자가 **5명(10안)** 있다.

| 시술명 | 안 |
|---|---:|
| `PRESBYOND` | 3 |
| `PRESBYOND+(P)` | 2 |
| `PRESBYOND+NEAR` | 2 |
| `PRESBYOND+NEAR+(P)` | 1 |
| `Mono+PRESBYOND` | 1 |
| `MONO+PRESBYOND+(P)` | 1 |

[find-vision-monthly-by-type.sql:24-47](../../backend/src/main/resources/sql/surgery/find-vision-monthly-by-type.sql#L24-L47)
의 분류 `CASE` 에 `PRESBYOND` 키워드가 **없어서 전부 `other` 로 떨어진다.**
일별([find-vision-daily-by-type.sql](../../backend/src/main/resources/sql/surgery/find-vision-daily-by-type.sql))도 같은 상태다.

`other` 는 유형별 컬럼이 없으므로 **표 어디에도 나타나지 않는다.**
다만 총계 `visionPatients` 는 `COUNT(DISTINCT cust_num)` 이라 **784 안에는 포함**돼 있다.

> 즉 **사람은 셌는데 넣을 칸이 없어 안 보이는 상태**다. 총원은 틀리지 않았다.

## ④ PIOL 합계 부풀림 (우리 문제)

화면의 PIOL 합계 168은 하위 유형을 단순 합산한 값이다 —
[surgeryCompositionUtils.ts:211](../../frontend/src/pages/surgery/surgeryCompositionUtils.ts#L211) `piolSum(d)`.

**양안에 서로 다른 렌즈를 넣은 환자 20명**이 두 유형에 각각 계상된다(예: 우안 ICL · 좌안 T-ICL).

| | 우리 표시 | 실제 |
|---|---:|---:|
| ICL | 44 | |
| T-ICL | 76 | |
| KPL | 19 | |
| T-KPL | 28 | |
| VIVA | 1 | |
| **PIOL 합계** | **168** | **148** (실인원) |
| 비중 | 21% | 18.9% |

저쪽 149와도 정확히 맞아떨어진다 — **실인원 148 + 장은애 오분류 1 = 149.**
저쪽은 환자당 한 유형만 세고, 우리는 중복해서 센 것이다.

항목별 차이도 중복 20명으로 전부 설명된다: ICL +3, T-ICL +8, KPL +3, T-KPL +6 = **20**.

### 중복은 PIOL 그룹 안에서만 발생한다

7월 전체 실측 — 유형별 합계 **804** vs 실인원 **784**, 차이 **20명**.
이 20명이 **전부 PIOL 내부 혼합**(168−148)이다.

| 유형 | 환자 |
|---|---:|
| 스마일프로 | 297 |
| 스마일 | 235 |
| 라섹계 | 74 |
| T-ICL | 76 |
| ICL | 44 |
| T-KPL | 28 |
| 라식계 | 25 |
| KPL | 19 |
| VIVA | 1 |
| `other`(= 프레스비욘드) | 5 |
| **합계** | **804** |
| **실인원** | **784** |

**라식·라섹·스마일 그룹은 서로 겹치는 환자가 없다.** 조사 전 예상과 달리 7월 기준
중복은 렌즈(PIOL)끼리만 발생했다.

## 고치는 방법

### ③ 프레스비욘드 — 분류 CASE 에 추가

바꿀 파일 2개. 각 파일에 우안/좌안 `CASE` 가 하나씩 있어 **총 4곳**이다.

| 파일 | 용도 |
|---|---|
| [find-vision-monthly-by-type.sql](../../backend/src/main/resources/sql/surgery/find-vision-monthly-by-type.sql) | 월별 유형 집계 |
| [find-vision-daily-by-type.sql](../../backend/src/main/resources/sql/surgery/find-vision-daily-by-type.sql) | 일별 유형 집계 |

```sql
-- 추가할 분기 (SMILE 계열보다 뒤, 라식/라섹보다 앞에 두면 안전)
WHEN o.OPERATIONR LIKE '%PRESBYOND%' THEN 'presbyond'
```

> `MONO+PRESBYOND` 는 기존 `monoVision`(`raw LIKE 'MONO%'`) add-on 에도 잡히므로
> 부가시술 컬럼과 중복 계상되지 않는지 함께 확인할 것.

**별도 항목으로 신설하는 경우 함께 바뀌는 것:**

| 마트 적재 | [upsert-surgery-monthly.sql](../../backend/src/main/resources/sql/mart/upsert-surgery-monthly.sql) · [upsert-surgery-daily.sql](../../backend/src/main/resources/sql/mart/upsert-surgery-daily.sql) |
| 마트 조회 | [select-surgery-monthly.sql](../../backend/src/main/resources/sql/mart/select-surgery-monthly.sql) · [select-surgery-daily.sql](../../backend/src/main/resources/sql/mart/select-surgery-daily.sql) |
| DTO | `SurgeryMonthlyItem` · `SurgeryDailyItem` |
| 서비스 | `SurgeryStatsService.mergeVision()` |
| 배치 | `SurgeryMartWriter` |
| 프론트 | [SurgeryCompositionPage.tsx](../../frontend/src/pages/surgery/SurgeryCompositionPage.tsx) 헤더 · [surgeryCompositionUtils.ts](../../frontend/src/pages/surgery/surgeryCompositionUtils.ts) `COLS` |

라식계에 편입하면 SQL 4곳만 고치면 되고 나머지는 그대로다.

### ④ PIOL 합계 — 실인원 기준으로

`piolSum(d)` 는 하위 유형 단순 합이라 구조적으로 중복을 못 피한다. 두 갈래다.

1. **집계에 `piolPatients`(DISTINCT 환자 수) 컬럼을 추가**해 합계로 쓴다 — 정확하지만 마트까지 손댄다.
2. **화면 라벨을 "유형 합(중복 포함)"으로 명시**한다 — 코드는 그대로, 오해만 없앤다.

같은 성격의 중복이 **라섹계·재수술 그룹 합계에도 있는지** 함께 점검할 것.

### ⚠️ 화면 반영 조건

일별·월별 수술 유형 집계는 **마트(`mart_surgery_daily` · `mart_surgery_monthly`)를 읽는다.**
SQL 은 배치 적재 소스라 **재적재해야 화면에 반영된다.**

```bash
curl -X POST 'http://localhost:18080/api/admin/batch/rerun?from=2024-01-01&to=2026-12-31&domain=SURGERY'
```

### 알려진 구조적 위험

백내장 제외가 **기간 무관 전 이력** 기준이다
([find-vision-monthly-by-type.sql:54-58](../../backend/src/main/resources/sql/surgery/find-vision-monthly-by-type.sql#L54-L58)).

7월에 시력교정 수술을 받은 사람에게 **나중에 백내장 행이 생기면 7월 과거 수치가 뒤늦게 줄어든다.**
7월 기준 해당자는 없지만, 과거 월 수치가 재조회 시점에 따라 달라질 수 있다는 뜻이다.
"기간 내 백내장 수술" 기준으로 좁히는 안을 검토할 것.

### 조사에 쓴 쿼리

```sql
-- 7월 시력교정 대상의 원본 시술명 전수 (분류 CASE 적용 + 미분류 확인)
WITH eyes AS (
  SELECT o.CUST_NUM, o.OPERATIONR AS raw FROM OPERATIONDATA o WITH(NOLOCK)
   WHERE o.OPERATION_DATE BETWEEN '2026-07-01' AND '2026-07-31'
     AND RTRIM(ISNULL(o.OPERATIONR,'')) <> ''
     AND NOT EXISTS (SELECT 1 FROM Cataract_Operationdata co WITH(NOLOCK)
                      WHERE co.CUST_NUM = o.CUST_NUM)
  UNION ALL
  SELECT o.CUST_NUM, o.OPERATIONL FROM OPERATIONDATA o WITH(NOLOCK) /* 좌안 동일 */
)
SELECT RTRIM(raw) AS 시술명, COUNT(*) AS 안, COUNT(DISTINCT CUST_NUM) AS 환자
FROM eyes GROUP BY RTRIM(raw) ORDER BY 안 DESC;

-- VIVA 흔적 전수 (백내장 제외 없이)
SELECT * FROM OPERATIONDATA WITH(NOLOCK)
WHERE OPERATION_DATE BETWEEN '2026-07-01' AND '2026-07-31'
  AND (OPERATIONR LIKE '%VIV%' OR OPERATIONL LIKE '%VIV%');

-- 유형 중복(양안 다른 유형) 환자 수
SELECT COUNT(*) FROM (
  SELECT CUST_NUM FROM typed GROUP BY CUST_NUM HAVING COUNT(DISTINCT t) > 1
) m;
```
