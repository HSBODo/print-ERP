# 원데이(당일OP) 검사 건수 — 기존 전산(레거시)과 대시보드 비교

> **대상 기간**: 2026-07-20 ~ 07-26 (07-26은 검사가 없어 실제로는 07-25까지)
> **비교 자료**: 기존 전산에서 뽑은 검사자 리스트 엑셀 · 운영 DB 직접 조회
> **조사일**: 2026-07-29

## 한 줄 요약

같은 기간에 **검사받은 사람은 양쪽 다 235명으로 똑같습니다.** 빠진 사람은 없습니다.
다만 그중 **몇 명을 원데이로 볼 것인가**가 다릅니다 — 기존 전산 88명, 대시보드 98명.

숫자만 보면 10명 차이지만, 실제로는 **18명이 서로 반대로 분류**돼 있습니다.
대시보드만 원데이로 센 사람이 **14명**, 기존 전산만 원데이로 센 사람이 **4명**이라
서로 상쇄되면서 겉으로는 10명 차이로 보이는 겁니다.

## 결정된 것 (2026-07-29)

두 가지 애매한 경우를 어떻게 셀지 정했습니다.

| 어떤 경우 | 어떻게 세기로 했나 | 지금 대시보드는 |
|---|---|---|
| 당일OP로 오셨는데 **수술을 못 하게 된 분** | **원데이** | 일반으로 세고 있음 → **고쳐야 함** |
| **재수술**을 당일에 받은 분 | **일반** | 이미 일반으로 세고 있음 → 그대로 두면 됨 |

이 결정을 반영하면 대시보드 원데이가 **93명 → 98명**이 됩니다.

## 1. 숫자

| | 기존 전산 | 대시보드<br>(지금) | 대시보드<br>(결정 반영 후) |
|---|---:|---:|---:|
| **검사받은 사람 전체** | **235** | **235** | **235** |
| ├ 원데이 검사 | **88** | 93 | **98** |
| ├ 일반 검사 | 143 | 138 | **133** |
| └ 드림렌즈 | 4 | 4 | 4 |
| | | | |
| 기존 전산과 원데이 차이 | — | +5 | **+10** |

**세로로 더하면 세 경우 모두 235명입니다.**

여기가 핵심입니다. **원데이에서 빠진 사람이 사라지는 게 아니라 일반 검사로 옮겨갈 뿐**입니다.
그래서 원데이가 10명 적으면 일반이 10명 많아집니다. 총원은 항상 똑같습니다.

### 세 열을 나란히 보면

- **기존 전산 88명** — 원데이가 가장 적습니다. 나중에 잡힌 재검사 예약 때문에 14명이 재검사로 빠져나갔기 때문입니다
- **대시보드 지금 93명** — 그 14명은 제대로 세지만, 수술을 못 하게 된 5분을 일반으로 빼고 있습니다
- **대시보드 반영 후 98명** — 그 5분까지 원데이로 세면 98명이 됩니다

결정을 반영하면 **기존 전산과의 차이가 5명에서 10명으로 벌어집니다.** 숫자는 멀어지지만, 그 10명은 전부 **기존 전산이 재검사로 빼놓은 사람과 재수술 4명**이라 이유가 분명해집니다.

## 2. 기존 전산 88명 → 대시보드 98명, 계산으로 확인

### 88 ＋ 11 ＋ 3 － 4 ＝ 98

| | 인원 | 어떤 분들인가 | 왜 더하나 / 빼나 |
|---|---:|---|---|
| **기존 전산 원데이** | **88** | 기존 전산이 원데이로 센 사람 | 출발점 |
| **＋** | **11** | 나중 날짜에 재검사 예약을 잡은 분 | 그날 당일OP 검사를 받으셨는데<br>기존 전산이 재검사로 빼놓음 |
| **＋** | **3** | 같은 날 재검사를 한 번 더 한 분 | 당일OP로 오셨는데<br>기존 전산이 재검사로 빼놓음 |
| **－** | **4** | 재수술을 당일에 받은 분 | 협의 결과 일반으로 세기로 함 |
| **＝ 대시보드 원데이** | **98** | | |

양쪽이 **똑같이 원데이로 센 사람은 84명**입니다. 여기서 갈립니다.

- 기존 전산 : 84 ＋ 4(재수술) ＝ **88**
- 대시보드 : 84 ＋ 14(기존 전산이 재검사로 빼놓은 분) ＝ **98**

### 검산 — 사람을 만들어내지 않았습니다

| | 원데이 | ＋ 일반 검사 | ＋ 드림렌즈 | ＝ 검사받은 사람 |
|---|---:|---:|---:|---:|
| 기존 전산 | 88 | 143 | 4 | **235** |
| 대시보드 | 98 | 133 | 4 | **235** |

**원데이가 10명 늘면 일반이 정확히 10명 줄어듭니다.** 총원 235명은 어느 쪽으로 세도 같습니다.
새로 만들어낸 사람도, 없앤 사람도 없습니다. **같은 235명을 어디에 넣느냐만 다릅니다.**

### 지금 대시보드가 93명인 이유

**98 － 5 ＝ 93**

수술을 못 하게 된 **5분**을 빼고 있어서입니다.
이번 결정("수술 못 하게 된 분도 원데이")대로 이 5분을 다시 넣으면 **98명**이 됩니다.

## 3. 왜 다른가 — 이유는 하나입니다

**기존 전산과 대시보드가 서로 다른 예약을 봅니다.**

| | 무엇을 보고 검사 종류를 정하나 |
|---|---|
| **기존 전산** | 그 환자의 **가장 최근 예약** — 날짜와 상관없이, 아직 오지 않은 미래 예약까지 |
| **대시보드** | 그 **검사받은 날**의 예약 |

원데이 검사를 받은 분은 그 자리에서 **재검사 예약을 잡고 가십니다.** 그러면 기존 전산은 나중에 잡힌 그 재검사 예약을 보고 **"이 사람은 재검사 환자"라고 바꿔버립니다.** 원데이에서 빠지는 거죠.

### 예를 들면

**서동혁 님**은 7월 21일에 원데이 검사를 받으셨습니다. 그런데 **12월에 재검사 예약**이 잡혀 있다는 이유로, 기존 전산에서는 **7월 원데이에서 빠져 있습니다.** 대시보드에서는 정상적으로 원데이로 잡힙니다.

### 이 방식의 문제

**지나간 달의 숫자가 나중에 바뀝니다.**

앞으로 예약이 하나 잡힐 때마다 기존 전산의 7월 숫자가 달라집니다. 지난주에 뽑은 7월 보고서와 이번 주에 뽑은 7월 보고서가 다를 수 있습니다.

대시보드는 그날 예약만 보기 때문에 **한 번 지나간 달의 숫자는 바뀌지 않습니다.** 마감된 숫자로 보고해야 하는 통계라면 이쪽이 안전합니다.

## 4. 다르게 잡히는 18명

결정을 반영한 뒤에도 아래 18명은 양쪽 분류가 갈립니다.

| 어떤 분들 | 인원 | 기존 전산 | 대시보드 |
|---|---:|---|---|
| ① 나중 날짜에 재검사 예약을 잡음 | **11** | 재검사 | 원데이 |
| ② 같은 날 재검사를 한 번 더 함 | **3** | 재검사 | 원데이 |
| ③ 재수술을 당일에 받음 | **4** | 원데이 | 일반 |

대시보드만 원데이로 센 14명 − 기존 전산만 원데이로 센 4명 = **10명 차이**

> 수술을 못 하게 된 5분은 결정 반영 후 **양쪽 다 원데이**가 되므로 여기서 빠집니다.

## 5. 앞으로 할 일

**고칠 것은 한 가지입니다.** 원데이를 세는 조건에서 **"수술 중단이 아닐 것"이라는 단서를 뺍니다.**

지금은 이렇게 되어 있습니다.

```
원데이 = 그날 당일OP 예약이 있고 + 수술이 중단되지 않았을 것
```

이걸 이렇게 바꿉니다.

```
원데이 = 그날 당일OP 예약이 있을 것
```

재수술은 결정대로 계속 빼둡니다.

### 주의할 점

- 같은 조건이 **5군데에 흩어져 있어 한 번에 같이** 고쳐야 앞뒤 숫자가 맞습니다
- 고친 뒤 **저장된 통계 데이터를 다시 만들어야** 하고, 그 과정에서 **지난 달 수치도 함께 바뀝니다**
- **상담 성공률은 거의 안 움직입니다** — 수술을 못 하게 된 분은 원래 성공률 계산에 안 들어가기 때문입니다
- 실제로 바뀌는 것은 **원데이 건수 · 일반 검사 수 · 일반검사 비율** 세 가지입니다

레거시는 고객의 최신 M 예약(`ORDER BY RESERVE_DATE DESC, RESERVE_NUM DESC`, `RESERVE_STATE <> 'C'` — 미내원 `'Y'` 포함) 기준으로 검사유형을 정한다. 이 기준으로 재조회하니 **6일치 검사OP 건수가 모두 정확히 일치**(16/20/8/5/9/26)해 원인이 확정됐다.

**원데이 판정 기준 — 변경 전 / 변경 후**
- 변경 전: 같은 날 `RESERVE_FLAG='M' AND RESERVE_JINRYO='5'`(검사OP) 예약이 `RESERVE_STATE IN ('I','H')`로 존재 **+ `STOP_YN <> 'Y'` + `CANCEL_CD = ''`**
- 변경 후: 같은 날 `RESERVE_FLAG='M' AND RESERVE_JINRYO='5'` 예약이 `RESERVE_STATE IN ('I','H')`로 존재 (중단/취소 조건 삭제)

`RESERVE_JINRYO='7'`(검사OP(Re) = 재수술 당일OP)은 **결정대로 계속 제외**한다.

총 검사자 235 = 시력교정 231 + 드림렌즈 4.
